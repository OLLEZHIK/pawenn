# Стандарт карточки заведения

Единый список того, что должно быть у **каждого** заведения в каталоге.
По нему пишутся все задачи на сбор данных: агент получает город (или
город + категории) и собирает для каждого заведения ровно эти поля.
Ничего сверх списка, ничего «по отдельной задаче на одно поле».

Решение владельца (2026-09-25). Где хранится: для новых городов —
`data/cities/<город>/businesses.csv` (см. `docs/playbooks/add-city.md`).
Братислава — там же (`data/cities/bratislava/`), правится напрямую. Цены
(`prices.csv`) и сводки отзывов (`review-insights/`) уже только в новой
папке. Новые задачи по Братиславе ставятся на новые файлы.

## Два языка

Сайт на двух языках: **английский** + **язык города** (для Словакии —
словацкий, `locale` из `city.json`). Правило простое:

- **Тексты** есть в двух версиях: поле без суффикса — английский,
  с суффиксом `_local` — язык города. Обе версии пишутся своими
  словами, естественно для каждого языка, не дословным переводом.
- **Факты** (адрес, телефон, часы, рейтинг, ссылки) от языка не
  зависят: одно значение, сайт сам подписывает их на нужном языке.
- **Коды** (`category`, `specialties`, `opening_hours`) — латиницей
  из фиксированных списков; перевод подписей делает сайт.

## Минимум качества — без него PR не принимается

Решение владельца (2026-09-25): карточка заведения — главный контент
сайта. Карточка без логотипа, рейтинга или часов работы выглядит
заброшенной. Поэтому у каждого города проверяется, **какая доля
заведений** имеет каждое поле:

| Поле | Минимум по городу |
|---|---|
| `short_description` + `_local`, `description` + `_local` | 100 % |
| `lat`, `lng` | 100 % |
| хотя бы одно из `phone` / `email` / `website` | 100 % |
| `google_maps_url` (карточка на Google Maps найдена) | 95 % |
| `opening_hours` | 90 % |
| `google_rating` + `google_rating_count` | 85 % |
| логотип (`logo_file`, файл существует) | 80 % |

**Пустое поле без следа поиска — ошибка.** Если логотипа, рейтинга или
часов нет, в `notes` обязательно строка в таком виде:

```
logo: none (site - text only, fb - photo of dog, ig - no account)
rating: none (Google Maps by name, address, phone - 3 ratings)
hours: none (site, Google Maps, fb - not published)
```

То есть **что не нашлось** и **где искали**. Где искать и в каком
порядке — `docs/playbooks/add-city.md`, разделы 4–5 и «Часы работы».
«<5 reviews» без описания поиска не считается.

**Проверка — скриптом, не на глаз.** Перед PR:

```
cd website && npm run check-city -- <город>
```

Скрипт печатает долю по каждому полю и список заведений, у которых
поле пустое без строки в `notes`. `NOT READY` — PR не открывать, а
дособрать. Вывод скрипта целиком вставить в описание PR. Ревьюер
запускает его сам и не мёржит PR с `FAIL`.

## Поля

**Обяз.** — у каждой записи должно быть заполнено, если заведение это
вообще публикует. Нет в открытом доступе — поле пустое, причина в
`notes`. Выдумывать нельзя никогда (`AGENTS.md`).

### 1. Кто это

| Поле | Обяз. | Язык | Что | Откуда |
|---|---|---|---|---|
| `category` | да | код | `GROOMING`, `VET_CLINIC`, `PET_HOTEL`, `DOG_TRAINING`, `PET_SHOP`, `PET_SITTING` | — |
| `name` | да | как есть | Название, как на вывеске/сайте | сайт, Google Maps |
| `slug` | да | латиница | Имя страницы: название без диакритики, нижний регистр, пробелы → `-`. При совпадении — добавить часть адреса (улицу или торговый центр): `super-zoo-avion`. **Slug уже существующего заведения не менять** — это адрес его страницы | генерируется |
| `logo_file` | да* | — | Файл в `website/public/logos/<город>/`. **Цель — логотип у ≥ 80 % записей** | сайт → иконки сайта → Facebook → Instagram → бренд сети; порядок и правила — `docs/playbooks/add-city.md`, раздел 5 |

\* пусто только если логотипа нет ни на сайте, ни в соцсетях; где смотрели — в `notes`.

### 2. Описание — на двух языках

| Поле | Обяз. | Что |
|---|---|---|
| `short_description` / `short_description_local` | да | Одна фраза до 100 символов для карточки в списке. Без названия и адреса (они уже на карточке) |
| `description` / `description_local` | да | 2–4 предложения для страницы заведения: что делают, для кого, чем отличаются |

Правила текстов — `docs/playbooks/add-city.md`, раздел 3 (только
проверяемые факты, без «лучший/профессиональный», ничего не копировать
дословно).

### 3. Где

| Поле | Обяз. | Что |
|---|---|---|
| `address` | да | `Улица номер, индекс Город` |
| `lat`, `lng` | да | Координаты, 5–6 знаков. Нужны для карты, маршрута, «Рядом со мной», **и по ним сайт сам определяет район** (районы агенты не собирают). **Мобильная служба без помещения** (ситтер, выгул, выездной грумер, платформа) — координат нет: поля пустые, в `notes` — `coords: none (mobile service, no premises)`. Центр города вместо адреса не ставить: это точка на карте там, где заведения нет (владелец, 2026-09-25; `check-city` такие координаты не пропускает) |
| `google_maps_url` | да | Ссылка на карточку места (кнопка «Маршрут») |
| `google_place_id` | да | Place ID, для будущего перехода на Places API |

### 4. Как связаться

| Поле | Обяз. | Что |
|---|---|---|
| `phone` | да | Международный формат: `+421 905 123 456` |
| `email` | да | Только публично указанный самим заведением |
| `website` | да | Официальный сайт, `https://…` |
| `instagram`, `facebook` | нет | Официальные страницы. У многих грумеров и ситтеров это единственный канал |

Хотя бы одно из `phone` / `email` / `website` обязательно, иначе
заведение не включаем.

### 5. Часы работы

| Поле | Обяз. | Что |
|---|---|---|
| `opening_hours` | да | `mo 08:00-12:00,14:00-19:00; tu 08:00-19:00; …; su closed`. Также `24h`, `closed`, `by-appointment` |
| `hours_source_url` | да | Где взяты часы |
| `hours_observed_at` | да | `YYYY-MM-DD` |

**Формат `opening_hours`:** дни `mo tu we th fr sa su`, после дня —
интервалы `HH:MM-HH:MM` через `,`, или `closed`, или `24h`; дни
разделены `;`. Пример:
`mo 08:00-12:00,14:00-19:00; tu 08:00-19:00; we 08:00-19:00; th 08:00-19:00; fr 08:00-17:00; sa 09:00-12:00; su closed`.
- День, о котором ничего не известно, не указывать.
- Приём только по записи — `by-appointment` вместо интервалов.
- Источник по приоритету: официальный сайт → официальная соцсеть →
  карточка Google Maps. Сайт и Google расходятся — брать сайт,
  расхождение в `notes`.
- Праздничные и сезонные часы («cez sviatky», «v lete») — только в
  `notes`, не как обычные.
- Место закрыто навсегда (сайт мёртв, на Google «Trvalo zatvorené») —
  новое не добавлять; уже опубликованное — `closed=yes` и `closed: (...)`
  в `notes` (§11).

### 6. Рейтинг

| Поле | Обяз. | Что |
|---|---|---|
| `google_rating` | да | Ровно как на карточке, `4.7`. Пусто, если оценок меньше 5 |
| `google_rating_count` | да | Число оценок. Пусто, если меньше 5 |
| `rating_observed_at` | да | `YYYY-MM-DD` |

### 7. Что говорят клиенты — на двух языках

Отдельный файл на заведение: `data/cities/<город>/review-insights/<slug>.json`
(для Братиславы тоже). Формат, правила и
порог (≥ 20 оценок и ≥ 5 отзывов с текстом за полгода) — `docs/playbooks/review-insights.md`.
Все `title` / `text` / `q` / `a` — парой `{ "en": …, "<locale>": … }`.

Главное правило оттуда: это **наша сводка** отзывов («N из M пишут…»),
а не отзывы от имени клиентов.

### 8. Только для ветклиник

| Поле | Что |
|---|---|
| `emergency_24_7` | `yes` — **только если заведение реально принимает круглосуточно** (правило ниже) |
| `emergency_note` / `emergency_note_local` | Любая другая неотложка, коротко, **на двух языках**: «emergency care until midnight» / «pohotovosť do 24:00», «night and weekend emergency care» / «nočná a víkendová pohotovosť», «24/7 emergency phone line» / «pohotovosť na telefóne 24/7» |
| `home_visits` | `yes`, если явно есть выезд на дом |
| `languages_spoken` | **Обязательно для ветклиник** (владелец, 2026-09-26): коды языков через `;` (`en; de; hu; uk; ru`), на которых заведение **явно** пишет, что обслуживает (сайт, соцсеть, разные языковые версии сайта). Местный язык не писать. Не указано нигде — поле пустое, в `notes`: `languages: none (site sk only, fb - not stated)`. По этому полю — запрос «english speaking vet» (страница-признак только в городах, где местный язык не английский; в англоязычном городе поле не обязательно); `check-city` не пропустит ветклинику без поля и без пометки |
| `specialties` | Коды через `;` **только** из списка `VET_SPECIALTIES` в `website/lib/vet.ts` (surgery, orthopedics, dentistry, dermatology, cardiology, ophthalmology, oncology, neurology, internal-medicine, reproduction, rehabilitation, exotics, ultrasound, x-ray, ct, mri, endoscopy, laboratory, hospitalization). Другие слова не придумывать: выезд — это `home_visits`; `check-city` не пропустит чужой код |

**Правило «Nonstop 24/7» (владелец, 2026-09-25).** Такие места попадают
на страницу «Nonstop», получают метку «Nonstop» и всегда считаются
«открыто сейчас». Ошибка здесь стоит дороже всего: человек с больным
животным ночью приедет к закрытой двери. Поэтому `emergency_24_7=yes`
ставится, только если выполнены оба условия:

1. **Заведение само прямо заявляет**, что открыто и принимает
   пациентов 24 часа, 7 дней в неделю («nonstop», «24/7», «otvorené
   nepretržite»), на своём сайте или в официальной соцсети. Каталоги,
   Google Maps и отзывы — не источник. В `notes` — строка
   `nonstop: <url, где это написано>`.
2. **`opening_hours` — `24h` все 7 дней** (`mo 24h; tu 24h; … su 24h`).
   Если часы приёма другие, это не nonstop, даже при заявленной
   неотложке.

Не nonstop (значит, `emergency_24_7` пустой, а текст — в
`emergency_note` / `emergency_note_local`):
- дежурный телефон 24/7 («pohotovosť na telefóne»);
- ночная или выходная неотложка при обычных часах приёма;
- неотложка по предварительному звонку, до определённого часа.

Сомневаешься — поле пустое, в `notes` — что нашёл. Скрипт
`check-city` не пропускает `emergency_24_7=yes` без часов `24h` на все
дни.

### 9. «Коротко о месте» — практические факты

Решение владельца (2026-09-26, `docs/research/place-page-needs.md`):
на странице места — что нужно знать до звонка: запись, оплата, для кого
услуга, условия. Столбец `facts` — коды через `;` **только** из списка
категории в `website/lib/facts.ts`:

| Категория | Коды |
|---|---|
| Ветклиника | `walk_in` (приём без записи), `appointment_only`, `online_booking`, `card_payment`, `parking`, `cats_waiting_room`, `pet_passport` (выдаёт европейский паспорт), `pharmacy_on_site`, `cat_friendly` (сертификат Cat Friendly Clinic) |
| Груминг | `cats`, `all_sizes`, `small_dogs_only`, `appointment_only`, `online_booking`, `card_payment`, `owner_can_stay` (можно остаться рядом), `natural_cosmetics`, `pickup_service` (привезут и отвезут) |
| Гостиница | `cats`, `small_dogs_only`, `vaccination_required`, `trial_stay` (пробный день / визит до заезда), `outdoor_run`, `supervision_24h`, `cage_free` (без клеток и вольеров), `medication` (дают лекарства), `photo_updates` |
| Дрессировка | `group_classes`, `private_lessons`, `puppy_classes`, `training_ground` (своё cvičisko), `home_training`, `behaviour_problems`, `certified_trainer`, `online_lessons`, `dog_sports` |
| Передержка | `dog_walking`, `cat_visits`, `home_sitting`, `boarding_at_sitter`, `insured` (страхование ответственности), `meet_greet` (знакомство до заказа), `medication`, `photo_updates`, `first_aid` |
| Зоомагазин | `delivery`, `vet_pharmacy`, `grooming_corner`, `card_payment`, `parking`, `click_collect`, `raw_food` (BARF), `aquarium_fish`, `exotic_supplies` |

**Это список, а не норма.** Записывать **все** пункты списка, которые
подтверждены, и только их; сколько найдётся — столько и есть. Девять
пунктов на категорию нужны, чтобы у места нашлось что-то полезное, даже
если об одном (например, о парковке) оно не пишет. Расширен владельцем
2026-09-27.

- Только то, что **место само прямо пишет** на своём сайте или в
  официальной соцсети. Нет кода — значит «не указано», а не «нет».
  Догадки («наверное, есть парковка») — не код.
- Противоречащие коды не ставить вместе: `walk_in` и `appointment_only`,
  `all_sizes` и `small_dogs_only`.
- Ничего не указано — поле пустое, в `notes`:
  `facts: none (site - nothing stated, fb - nothing)`.
- Минимум по городу — 80 % мест с кодами или пометкой; `check-city`
  проверяет коды, противоречия и пометки.
- Сайт показывает коды короткими пунктами и делает из них ответы на
  частые вопросы («Treba sa objednať?»).

### 10. Не собираем

- `photo_urls` — **не собирать** (владелец, 2026-09-26). Фото с чужих
  сайтов не показываем (авторские права), сгенерированные не ставим,
  шапку карточки ведёт логотип. Столбец в файле остаётся пустым.
- `animals` — **не собирать** (владелец, 2026-09-25). Столбец остаётся
  ради совместимости, старые значения не трогать. Фильтра по животным
  в списках мест больше нет (владелец, 2026-09-27): без данных он
  только менял порядок.
- Для не-ветклиник `languages_spoken` — только если заведение само
  явно это пишет; искать специально не нужно.

### 11. Служебное (посетителям не показывается)

| Поле | Что |
|---|---|
| `source_url` | Главный источник данных |
| `observed_at` | Дата сбора `YYYY-MM-DD` |
| `notes` | Что не нашлось и почему |
| `closed` | `yes` — **место закрылось навсегда уже после того, как попало на сайт** (владелец, 2026-09-26). Строка остаётся, чтобы старый адрес страницы уводил на список категории; на сайте места нет. В `notes` обязательно `closed: (<где видно>, <дата>)`. Новое место, которое уже закрыто, **не добавлять вовсе**. `check-city` не пропустит `closed=yes` без пометки и строку, где в `notes` написано «closed / zatvorené», но `closed` пустой |

## Цены — 6 главных услуг на категорию

Решение владельца (2026-09-25): цены ищем **не на весь прайс, а только
на 6 самых востребованных услуг** в каждой категории. Так цены у разных
заведений можно сравнивать, и агент не тратит время на переписывание
длинных прайсов.

Выбор услуг — по тому, что владелец питомца чаще всего ищет с
вопросом «сколько стоит», и что заведения реально публикуют.

### Главное правило: одна услуга — одно содержание

Решение владельца (2026-09-25). Цены разных заведений сайт ставит рядом
и сравнивает (индикатор «дорого/дёшево»). Поэтому для каждого кода ниже
в колонке «Что считать» написано, **что входит в цену**, и записывается
**то, что клиент реально заплатит за эту услугу целиком**:

- Заведение пишет части отдельно («operácia 42 € + anestézia 30 €»,
  «čip 5 € + registrácia 25 €») — **сложить** и записать сумму; в
  `notes` — обе строки прайса.
- Сложить нельзя (например, цена наркоза не опубликована) — записать то,
  что есть, и поставить `partial=yes` с короткой пометкой, чего не
  хватает (`note`: «without anaesthesia» / `note_local`: «bez
  anestézy»). Такая цена показывается на сайте с пометкой, но **не
  участвует в сравнении**.
- Цена не за услугу целиком, а за час или километр — `unit` (`per_hour`,
  `per_km`). Сайт покажет «25 € / hod.», в сравнении такая цена тоже не
  участвует.
- Цена включает больше, чем стандарт (например, стационар) — записать
  её как есть, без `partial`, и коротко указать это в `note`. Сайт
  покажет её с пометкой, но **в сравнении она не участвует**: цена
  «операция + стационар» рядом с «операция + наркоз» выглядела бы
  завышенной (решение 2026-09-25). Поэтому `note` у полной цены — только
  когда она действительно включает больше стандарта.

### Сравнение с рынком города

Решение владельца (2026-09-25). Каждую цену и каждое заведение сайт
сравнивает с рыночной ценой города. Код — `website/lib/priceMarket.ts`,
логика одна для всех городов и категорий:

1. **Цена заведения за услугу** — его самая низкая сравнимая цена по
   этому коду (цена «от»; при диапазонах веса — для самой маленькой
   собаки). Так все заведения меряются одинаково.
2. **Рыночная цена услуги в городе** — медиана цен заведений этой
   категории. Считается, только если услугу публикуют **не меньше 3
   заведений**. Медиана, а не среднее: одна дорогая больница не должна
   сдвигать «рынок».
3. **Сравнимые цены** — без `partial`, без `unit` (за час, за км) и без
   `note` (включает больше стандарта). Остальные показываются, но в
   медиану и в сравнение не входят.
4. **Уровень заведения** — медиана отношений «его цена / рыночная» по
   всем его услугам, где есть рыночная цена. Округлённый процент:
   «на 40 % выше рынка», «на 10 % ниже рынка».
5. **Значки €** (как в Google Maps) — из этого процента, пороги
   фиксированные:

   | Значки | Отклонение от рынка | Подпись |
   |---|---|---|
   | € | дешевле больше чем на 25 % | «на X % ниже рынка» |
   | €€ | дешевле на 8–25 % | «на X % ниже рынка» |
   | €€€ | в пределах ±7,5 % | «Рыночная цена» |
   | €€€€ | дороже на 8–25 % | «на X % выше рынка» |
   | €€€€€ | дороже больше чем на 25 % | «на X % выше рынка» |

   Нет ни одной услуги с рыночной ценой — значков нет.

Где видно: значки с подписью — в списках и в шапке карточки. Таблица
цен на карточке стоит **сразу после контактов** (владелец, 2026-09-25):
цена — то, ради чего сравнивают. В таблице цен карточки у каждой услуги — «на X % выше/ниже рынка ·
медиана в городе N € · M заведений». Из-за этого **каждая новая
сравнимая цена улучшает сравнение для всего города** — сбор цен
остаётся приоритетом.

### Файл и правила

Файл — `data/cities/<город>/prices.csv` (для Братиславы сюда 2026-09-25
перенесены собранные цены груминга и ветклиник):

```
business_slug,price_code,weight_from_kg,weight_to_kg,price_from,price_to,currency,source_url,observed_at,notes,unit,partial,note,note_local
```

Последние четыре колонки добавлены 2026-09-25. В старых файлах их может
не быть: сайт читает оба варианта.

- `business_slug` — `slug` заведения из `businesses.csv`.
- `price_code` — **только** коды из таблицы **категории этого
  заведения** (у ветклиники нет `nail_trim` и `vaccination_cat`, у
  передержки — кодов дрессировки). Услуги не из списка не записывать.
  `check-city` не пропустит чужой код.
- `weight_from_kg` / `weight_to_kg` — диапазон веса ровно как у
  заведения («do 10 kg» → пусто / `10`; «nad 40 kg» → `40` / пусто).
  Цена не зависит от веса — оба пусто.
- `price_from` / `price_to` — числа в валюте города. Фиксированная цена —
  одно число в обоих полях. «od 30 €» — `price_from=30`, `price_to` пусто.
  Цена зависит от размера, а размер в прайсе без веса (S/M/L) —
  `price_from` = цена самого маленького, `price_to` = самого большого;
  все цены — в `notes`. Не оставлять `price_to` пустым, если верхняя цена
  известна.
- `source_url` — страница (или PDF) с ценой. Только официальный сайт
  заведения или его официальная соцсеть (опубликованный прайс).
  Цены «по телефону», из каталогов и отзывов не брать.
- `notes` — **строка прайса в оригинале**, как у заведения (на языке
  города), плюс уточнения. Посетителям не показывается; нужна для
  проверки.
- `unit` — пусто, если цена за услугу целиком (так почти всегда).
  `per_hour` — за час, `per_km` — за километр.
- `partial` — `yes`, если в цене нет части того, что входит в услугу по
  стандарту, и сложить нельзя. Иначе пусто.
- `note` / `note_local` — **показываются посетителям** рядом с ценой.
  Коротко, до 40 символов, на английском и на языке города: «without
  anaesthesia» / «bez anestézy», «incl. hospitalisation» / «vrátane
  hospitalizácie». Обязательны при `partial=yes`, в остальных случаях —
  только если без пометки цену поймут неправильно. **Не повторять в
  `note` название услуги** («clinical examination», «nail trim»):
  строка с `note` показывается, но не сравнивается с рынком.
- Переводить ничего не нужно: названия услуг на двух языках — в таблицах
  выше, их подставляет сайт.
- Услуга есть, а цены нет («cena dohodou», «podľa rozsahu») — строку не
  добавлять. Заведение вообще не публикует цены — ни одной строки, в
  `notes` заведения в `businesses.csv`: `prices: not published`.

## Проверка перед PR (для каждого агента)

Общий стандарт и блок самопроверки для описания PR —
`docs/playbooks/quality.md`. Здесь — то, что относится к данным карточки.

- Логотип — до 200 КБ (достаточно 512 px); `check-city` не пропустит
  файл тяжелее.
- `npm run check-city -- <город>` печатает `READY` (раздел «Минимум
  качества»); его вывод — в описании PR.

- Каждое **обяз.** поле либо заполнено, либо пусто с причиной в `notes`.
- Все тексты есть в двух языках: нет `short_description` без
  `short_description_local` и наоборот; то же для `description` и
  review-insights.
- `slug` уникален в городе; файл review-insights назван тем же slug.
- В `prices.csv` только коды из раздела «Цены», у каждой строки есть
  `source_url`.
- Каждая цена соответствует колонке «Что считать»: части сложены, а где
  сложить нельзя — `partial=yes` и `note` / `note_local`.
- Координаты — адрес заведения, а не центр города; у мобильной службы без
  помещения их нет, а в `notes` — `coords: none (mobile service, no premises)`
  (раздел 3). `check-city` ловит координаты в центре города.
- `emergency_24_7=yes` только по правилу «Nonstop 24/7» (раздел 8):
  прямое заявление на сайте заведения и часы `24h` все 7 дней.
- В описании PR — таблица заполненности: сколько записей имеют каждое
  поле из разделов 1–8 и сколько заведений дали хотя бы одну цену.
