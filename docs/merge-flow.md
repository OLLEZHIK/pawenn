# Как всё мержится: одна страница

Обновлено 2026-10-06 («левая рука», по слову владельца: «чтобы всё было очень логично»). Подробности — в `AGENTS.md` и `docs/pc-agents/pipeline.md`; здесь только схема.

## Три потока

```
ДАННЫЕ ГОРОДА   агент ──PR──► city/<город> ──один PR──► main
                       (мержит диспетчер)     (проверка «левой руки», кнопку нажимает владелец)

КОД САЙТА       claude/<имя> ──один PR за заход──► main
(website/, языки, дизайн)                          (кнопку нажимает владелец)

ДОКУМЕНТЫ       claude/<имя> ──PR──► main          (tasks/, docs/, AGENTS.md;
                                                    сборку сайта не запускают)
```

| Поток | Кто делает | Куда PR | Кто мержит | Что проверяется |
|---|---|---|---|---|
| Данные, партия (кусок 10 мест) | агент Antigravity `agyN` | `city/<город>` | диспетчер (пачкой, `AGENTS.md`) | `agent-check`, `sanity`, ворота `gate` |
| Данные, город целиком | диспетчер собирает, «левая рука» открывает PR | `main` | владелец (кнопка «Bypass rules and merge → Create a merge commit») | `ready-city`, `check-city` READY, `verify-city` VERIFIED, выборка |
| Код сайта, языки, дизайн | «левая рука» / CLI | `main`, **один PR за заход** | владелец (та же кнопка) | `tsc`, `check-guides`, сборка локально, `next start` |
| Документы (`tasks/`, `docs/`, `AGENTS.md`) | любая сессия Claude | `main` | владелец (та же кнопка) | глазами; сборку Vercel не запускают |

## Где что видно

- **Города и задачи:** `tasks/README.md` (индекс), строка «Сейчас:» в каждом файле задачи.
- **Диспетчер ↔ «левая рука»:** доска — `docs/pc-agents/board.md` (в `main`, пишу я) и `board-from-dispatcher.md` (ветка `pcd/board`, пишет диспетчер).
- **Выкладка сайта:** только ветка `main` (`website/vercel.json`). Ветки Vercel не собирает, поэтому «посмотреть превью» нельзя: проверка идёт локально.

## Правила, чтобы не запутаться

1. **В `main` — только PR.** Прямых пушей нет ни у кого.
2. **Один мерж с кодом сайта за заход.** Правки `website/` и `data/` копятся в одной ветке (сейчас `claude/sanity-de`) и уходят в `main` одним PR вместе со сборным PR города.
3. **Данные города в `main` — только целым городом** (`city/<город>`), кусками в `main` не идёт.
4. **PR агентов в `city/*` не трогаю ни я, ни владелец**: их ведёт диспетчер.
5. **Критическая инфраструктура** (Vercel, секреты, база, новые аккаунты агентов) — только по слову владельца в чате.
6. **Кнопка мержа.** У PR с коммитами Claude правило ветки `main` требует «дополнительное одобрение» (`require_extra_approval_for_unattributed_changes`), поэтому владельцу нужно выбрать «Bypass rules and merge». Если это мешает — можно выключить этот пункт в ruleset (настройки GitHub, решение владельца): тогда кнопка станет обычной.

## Как смержить PR владельцу (30 секунд)

Открыть PR → прокрутить вниз → галочка «Merge without waiting for requirements» уже стоит → стрелка рядом с кнопкой → **Create a merge commit** → **Bypass rules and merge** → **Confirm**.
