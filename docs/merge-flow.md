# Как всё мержится: одна страница

Обновлено 2026-10-10 (оркестратор, по слову владельца: «левой руки» больше нет, мержит оркестратор). Подробности — в `AGENTS.md` и `docs/pc-agents/pipeline.md`; здесь только схема.

## Три потока

```
ДАННЫЕ ГОРОДА   агент agyN ──PR──► city/<город> ──один PR──► main
                       (мержит автомерж диспетчера)   (проверка и мерж — оркестратор)

КОД САЙТА       claude/<имя> или cli/<имя> ──один PR за заход──► main
(website/, языки, дизайн)                          (мержит оркестратор)

ДОКУМЕНТЫ       claude/<имя> ──PR──► main          (tasks/, docs/, AGENTS.md;
                                                    сборку сайта не запускают)
```

| Поток | Кто делает | Куда PR | Кто мержит | Что проверяется |
|---|---|---|---|---|
| Данные, партия (кусок 10 мест) | агент Antigravity `agyN` (15 контейнеров) | `city/<город>` | автомерж диспетчера (`AGENTS.md`, «Критическая инфраструктура», п. 1) | `agent-check`, `sanity`, ворота `gate` |
| Данные, город целиком | диспетчер собирает и открывает PR | `main` | оркестратор | `ready-city`, `check-city` READY, `verify-city` VERIFIED, выборка |
| Код сайта, языки, дизайн | CLI / оркестратор по слову владельца | `main`, **один PR за заход** | оркестратор | `tsc`, `check-guides`, сборка локально, `next start` |
| Документы (`tasks/`, `docs/`, `AGENTS.md`) | любая сессия Claude | `main` | оркестратор | глазами; сборку Vercel не запускают |

Владелец вправе мержить сам в любой момент. Исполнители в `main` не мержат и не пушат.

## Автоматический режим (с 2026-10-10)

Владелец называет город — дальше всё идёт без него: оркестратор ставит задачу диспетчеру на доске, диспетчер собирает город через 15 контейнеров, оркестратор по расписанию обходит PR и ветки, вливает прошедшее проверки и мержит готовый город в `main` с `[deploy]` в заголовке мерж-коммита — выкладка после каждого города. Владельцу пишет отчёт; вопросы — только по деньгам, базе, секретам, настройкам GitHub/Vercel и неснимаемым красным воротам.

## Что приносит диспетчер к сборному PR

`ready-city`, **`verify-city` с ПК** (облако даёт шум из-за 403), отметка выборки. Оркестратор делает свой быстрый `check-city` + `sanity` и сверяет с `main`. Подробности — `pc-agents/pipeline.md`.

## Где что видно

- **Города и задачи:** `tasks/README.md` (индекс), строка «Сейчас:» в каждом файле задачи.
- **Диспетчер ↔ оркестратор:** доска — `docs/pc-agents/board.md` (в `main`, пишет оркестратор) и `board-from-dispatcher.md` (ветка `pcd/board`, пишет диспетчер; в `main` его нет).
- **Выкладка сайта:** только ветка `main` (`website/vercel.json`). Ветки Vercel не собирает, поэтому «посмотреть превью» нельзя: проверка идёт локально. Обычные коммиты в `main` уходят в выкладку пачкой не чаще раза в 20 часов (`website/scripts/vercel-ignore-build.sh`); **мерж готового города и срочное — с `[deploy]` в заголовке мерж-коммита, выкладка сразу.**

## Правила, чтобы не запутаться

1. **В `main` — только PR.** Прямых пушей нет ни у кого.
2. **Один мерж с кодом сайта за заход.** Правки `website/` и `data/` копятся в одной ветке и уходят в `main` одним PR вместе со сборным PR города.
3. **Данные города в `main` — только целым городом** (`city/<город>`), кусками в `main` не идёт. Исключение — правки уже влитого города (например, пересчёт цен): PR прямо в `main`, если ветка `city/<город>` уже совпадает с `main`.
4. **PR агентов в `city/*` вливает автомерж диспетчера**; оркестратор вручную вливает их только по слову владельца, предварительно слив все PR локально и сравнив `check-city` с базой.
5. **Дубли** (два PR одного куска разными агентами) — вливается первый, второй закрывается.
6. **Проблемное место заменяем, а не чиним** (`AGENTS.md`, раздел «Проект»).
7. **Критическая инфраструктура** (Vercel, секреты, база, новые аккаунты агентов) — только по слову владельца в чате.
8. **Кнопка мержа.** Если правило ветки `main` требует «дополнительное одобрение» для коммитов Claude, мерж идёт через «Bypass rules and merge» (решение владельца).
