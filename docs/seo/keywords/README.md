# Ключевые слова по языкам

Решение владельца (2026-09-26): **каждая страница называется так, как
люди чаще всего ищут её на своём языке.** Исследование идёт отдельно по
каждому языку сайта. Результат — заголовки, H1, описания и (редко)
адреса страниц по реальным запросам, а не по нашим догадкам.

| Язык | Файл | Статус |
|---|---|---|
| Словацкий (`sk`) | `sk.md` | Собрано (Trends + подсказки, без Planner), PR #100; title на сайте применены 2026-09-26 |
| Английский (`en`) | `en.md` | Собрано (Trends + подсказки, без Planner), PR #101; title признаков применены 2026-09-26. Категории — ещё `../english-keywords.md` |
| Новый язык | `<locale>.md` | Шаг в `docs/playbooks/add-language.md`: сначала запросы, потом слаги |

## 1. Как собирать цифры

Облачный Claude Code данные Google не видит (сеть закрыта), поэтому
цифры собирает агент на компьютере владельца (Antigravity) или сам
владелец. Источники по убыванию надёжности:

1. **Google Ads Keyword Planner** (бесплатно с аккаунтом Google Ads,
   кампанию запускать не нужно): «Узнать число запросов и прогнозы» →
   вставить все варианты из карты → Местоположение: страна (для `sk` —
   Slovakia; если даёт — отдельно Bratislava), Язык: язык страницы.
   Берём «Среднее число запросов в месяц». Без активной кампании
   Planner даёт диапазоны (10–100, 100–1K) — пишем диапазон как есть.
2. **Google Trends** (`trends.google.com`), страна, 12 месяцев:
   сравнить до 5 вариантов одного смысла. Нужен, когда Planner даёт
   одинаковый диапазон: Trends показывает, какой вариант больше.
3. **Подсказки Google** (`google.<tld>` в режиме инкогнито, язык
   страны): ввести основу («veterin», «strihanie ps») и записать
   подсказки. Так находятся варианты, которых нет в карте.
4. **«Похожие запросы» и «Люди также спрашивают»** внизу выдачи —
   идеи для FAQ и текстов.
5. **Google Search Console** сайта — после того как страницы
   поживут в индексе 2–3 месяца: реальные запросы, по которым нас
   показывают. Тогда карту пересматриваем по ним.

Каждая цифра — с источником и датой. Нет данных — `—` (инструмент
недоступен) или `н/д` (инструмент открыт, но цифры не дал), и причина
в начале файла. **Никогда не оценка**: без доступа к Planner колонка
Planner — `—` во всех строках.

Ограничения инструментов:
- **Trends** не считает редкие запросы («veterinár petržalka»,
  большинство английских): на них он пишет «Недостаточно данных» →
  `н/д`. Индексы сравнимы только **внутри одного сравнения** (до 5
  запросов за раз); запрос в группе один — индекс 100 ничего не
  значит, писать `н/д (один в группе)`. У всех запросов группы 0 —
  это тоже «данных нет» (`н/д`): у лидера сравнения всегда 100.
  Совсем малый индекс рядом с лидером — `<1`, как в Trends. Не пересчитывать индексы
  между группами и не выводить их из «базового термина».
- **Подсказки** доказывают, что запрос существует, но не частоту.
- Если по смыслу нет цифр ни из Planner, ни из Trends — решение
  можно принять по подсказкам и языку, но пометить в «Решение»:
  «без цифр».

## 2. Формат таблицы в `<locale>.md`

Одна таблица на тип страницы. Варианты одного смысла — рядом:

| Смысл | Вариант запроса | Planner, мес. | Trends (0–100) | Подсказка | Решение |
|---|---|---|---|---|---|
| ветеринар в городе | veterinár bratislava | 1K–10K | 100 | да | **главный** |
| ветеринар в городе | veterina bratislava | 100–1K | 45 | да | второй: в описание |

`Решение`:
- **главный** — самый частый вариант смысла; идёт в `<title>` и H1;
- **второй** — заметный вариант: в meta description, подзаголовок,
  текст, FAQ (Google понимает синонимы, но совпадение слов помогает);
- **нет** — почти нет спроса, не используем.

## 3. Правила применения

- **Title и H1** — по главному варианту. Меняем свободно: это не
  ломает ссылки.
- **Адрес (слаг)** — живой и в индексе, поэтому меняем, только если
  главный вариант **явно** сильнее текущего (минимум на ступень
  Planner — например 1K–10K против 100–1K — или вдвое по Trends) и
  речь о странице с заметным спросом. Смена = 301 со старого адреса.
  Для нового языка слаги выбираем по исследованию **до** запуска.
- **Формы слов** — в словацком запросы бывают в разных падежах и
  числах («veterinár» / «veterinári»). Google их склеивает; выбираем
  форму, которая естественно читается в заголовке.
- **Диакритика** — люди часто пишут без неё («psi salon»). Для Google
  это один запрос; в текстах пишем правильно, в адресах — без неё.
- **Результат — шаблон языка, а не решение для одного города.** Главный
  вариант смысла («strihanie psov», «zverimex», «veterinárna
  pohotovosť») идёт в шаблон заголовка `{вариант} {в городе}` и
  работает для каждого города этого языка (Братиславы, Кошице, Жилины…).
  Город в запросах исследования — только чтобы поймать локальный
  интент; новый город того же языка **нового исследования не требует**.
- **Районы отдельно не исследуем** (владелец, 2026-09-26: Братислава —
  образец, не цель): районная страница берёт тот же шаблон.

## 3.1 Названия услуг для страниц цен (владелец, 2026-09-27)

У каждой услуги из цен два названия:
- **короткая подпись** для таблиц цен («Pes, noc», «Kompletná úprava») —
  `lib/services.ts`, поля `en`, `sk`…;
- **поисковое название** для страницы цены услуги — title, H1 и вопрос
  FAQ («Hotel pre psov na noc v Bratislave – od 16 €») — поле `seo`.
  Оно обязательно для каждого языка: без него сайт не собирается.

*Было:* заголовок «Pes, noc v Bratislave – od 17 €» — техническая
подпись прайса, так никто не ищет.

**Как вывести поисковое название — по шагам:**
1. Взять **главный** вариант запроса этой услуги из карты языка,
   раздел «Цены» (`<locale>.md`). Нет строки для услуги — сначала
   исследование по этому README, **не придумывать**.
2. Убрать из запроса слова цены и город: «cena», «cenník», «koľko
   stojí», «price», «cost», «cena», «ile kosztuje», «<город>», «v/w/in
   <городе>». Остаток с заглавной буквы — это название
   («strihanie psa cena» → «Strihanie psa»).
3. Оставить объект, если его пишут в запросе: «strihanie **psa**»,
   «hotel pre **psov**», «čipovanie **psa**». Не сокращать до термина
   салона («Kompletná úprava»).
4. Цена за единицу — единица словами, как в запросе: «na noc», «na
   deň», «per night», «na godzinę». Никогда «Pes, noc», запятые-списки,
   косые черты, сокращения.
5. Два варианта с близким спросом (или народный + точный) — главный,
   второй в скобках: «Kastrácia fenky (suky)».
6. Длина — до 45 знаков, чтобы «<название> v <городе> – od X € |
   Pawenn» помещалось в выдачу (~60).
7. **Страница уже в топ-10 по своему запросу — название не менять**
   (смена заголовка может стоить позиции). Сейчас так:
   «Kastrácia (sterilizácia) mačky» — 4-е место в Google по
   «Kastrácia mačky v Bratislave» (владелец, 2026-09-27).
8. Адрес страницы (слаг, `lib/priceSlugs.ts`) от названия не зависит и
   не меняется (§3).

**Для нового языка** поисковые названия — часть шага 2
(`docs/playbooks/add-language.md`): переводчик выводит их из карты
ключевых слов по шагам 1–6, а не переводит короткую подпись.

## 4. Где это на сайте

| Что | Где в коде |
|---|---|
| Название категории, title, описание | `website/lib/categories.ts`: `LABELS`, `SEO_TITLE`, `BLURBS`, `SLUGS` |
| Страницы признаков (nonstop, sobota…) | `website/lib/attributePages.ts` (слаги), словарь `attributes` в `lib/dictionaries/<locale>.ts` |
| Обзор цен категории (title, H1) | `website/lib/categories.ts`: `PRICES_NAME` — главный запрос цен категории из раздела 3 карты («Veterina», «Dog grooming prices») |
| Страницы цен | `website/lib/priceSlugs.ts` (слаги услуг), `lib/services.ts` (короткие подписи и поле `seo` — поисковые названия, §3.1), словарь `prices` |
| Главная, FAQ | словари `lib/dictionaries/<locale>.ts` |

Применяет результат исполнитель сайта (CLI, «правая» или «левая рука»)
отдельным PR, после мерджа файла `<locale>.md` с цифрами.
