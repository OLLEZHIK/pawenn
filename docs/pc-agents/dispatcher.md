# Диспетчер на ПК: конвейер, поправки, уроки

Claude Code CLI на ПК (`D:\docker\shop`, в `.git/agent` —
`Claude Code CLI (ПК, диспетчер)`) — мастер участка. Сам ничего не
собирает (владелец, 2026-10-01). Его работа: держать каждого агента
занятым, ловить ошибки процесса, пока они дёшевы, поправлять агента и
записывать урок, чтобы ошибка не повторилась (владелец, 2026-10-02).

## 1. Конвейер: путь каждого куска работы

```
очередь → работа → GATE PASS → PR → agent-check → напарник → проверяющий → мерж (владелец)
            ▲                          │              │            │
            └──────── «Поправка» ◄─────┴──────────────┴────────────┘
```

| Этап | Кто | Выход |
|---|---|---|
| очередь | диспетчер | строка в `D:\docker\status.md` |
| работа | агент | куски по 10, каждый с `GATE PASS` и штампом |
| PR | агент | PR с «Самопроверкой», итог в формате п. 4 |
| agent-check | диспетчер | `npm run agent-check -- origin/<ветка> [база]`: OK или «Поправка» |
| напарник | другой агент | комментарий `## Проверка напарника (ПК N)` (`pipeline.md`) |
| проверяющий | облачный Claude Code | «Готово к мержу» или «Ревью N» в файле задачи |
| мерж | владелец | — |

Возврат с любого этапа — «Поправка» тому же агенту в ту же ветку.

## 2. Кому что давать: порядок для свободного агента

Освободился агент — дать первое, что есть, сверху вниз:

1. **Поправка или «Ревью» к своему PR** — исправленное идёт дальше по
   конвейеру, новое ждёт.
2. **Проверка напарника** чужого PR — иначе PR стоят и копятся.
3. **Следующий кусок своей задачи** — если у задачи меньше 3 PR на
   проверке.
4. **Новая задача** — из `tasks/pc-*.md`, у которой ещё нет ветки
   `pcN/<slug>`. Кому и в каком порядке — решает диспетчер сам
   (владелец, 2026-10-02): сначала поле `**Срочность:**`, потом
   задачи, от которых зависят другие, потом более старые; агента — по
   `capabilities.md` (❔ — только пилот, ❌ — не давать) и по
   «Зависимостям» задачи (вход в Google, сданный экзамен). Ветка —
   `pcN/<slug>`, где N — номер выбранного контейнера. Старые `pcN-*` и
   `pcd-warszawa-and-reviews.md` — доделать по их очередям.
5. Нечего — агент свободен, отметить в отчёте.

Одна задача — одному контейнеру. Начатую ветку не передавать другому,
пока автор не упёрся в лимит (п. 6).

## 3. Поручение: всегда по одному шаблону

Файлом в контейнер, в PowerShell (одинарные кавычки — PowerShell их не трогает):
`docker cp D:\docker\task-agyN.md agyN:/tmp/task.md`, затем
`docker exec -d -u ubuntu agyN bash -lc 'cd ~/shop && agy -p "$(cat /tmp/task.md)" --dangerously-skip-permissions > ~/agy-logs/<дата>-<задача>.log 2>&1'`
(клон в контейнерах — `~/shop`; `-d` — агент работает и после выхода
диспетчера, его ответ и блок ИТОГ — в логе; запуск без подтверждений —
только пока владелец у ПК, `AGENTS.md`, «Критическая инфраструктура», п. 6).

```
Ты — Antigravity (ПК N). Перед работой:
1. git fetch origin && git checkout main && git pull
2. Прочитай AGENTS.md, docs/playbooks/quality.md, docs/pc-agents/lessons.md — все уроки.
3. Задача: tasks/<файл>.md. Делай то, что в строке «Сейчас:», и только это.
<Если есть: Поправка — текст из п. 5.>
Запрещено: менять website/scripts/**, docs/**, AGENTS.md, чужие ветки, пушить в main.
Нет данных — «—» и причина. Застрял — вопрос в PR и остановись.
В конце — последним сообщением блок ИТОГ (формат ниже), ничего после него.
```

## 4. Итог агента — одна форма, чтобы читать за секунды

```
ИТОГ
задача: tasks/<файл>.md
ветка: pcN/<…>
PR: <ссылка или «нет»>
gate: PASS <куски> | FAIL <кусок> | не нужен
состояние: сдано | ждёт ответа | лимит | ошибка среды
вопрос: <одна строка или «нет»>
```

Нет блока ИТОГ — это тоже поправка (У-04: работа не сдана).

## 5. Поправка: право диспетчера исправлять агента

**Право (владелец, 2026-10-02):** диспетчер останавливает агента и
возвращает его работу на исправление, не дожидаясь ревью, если ошибка
видна без проверки фактов:

- `agent-check` — FAIL;
- нет блока ИТОГ или PR, `gate` FAIL оставлен, кусок больше 10 мест;
- агент нарушил поручение (другая задача, чужая ветка, пуш в `main`);
- напарник или проверяющий написал правки, а агент их не взял;
- лог показывает догадки вместо `none` («примерно», «вероятно», «обычно»).

**Не право:** решать, верен ли факт о месте, менять данные или код
агента самому, менять правила (`quality.md`, `AGENTS.md`), отменять
ревью проверяющего. Спор «верно ли» — к напарнику и проверяющему.

**Текст поправки** — в поручение, перед задачей:

```
ПОПРАВКА (диспетчер, <дата>)
Что не так: <факт: файл, строка, вывод agent-check>
Почему нельзя: <урок У-NN или правило quality.md N>
Как исправить: <конкретно, по шагам; в той же ветке, новым коммитом>
Проверка: <команда, которая должна пройти: agent-check / gate>
```

## 6. Урок: чтобы ошибка не повторилась

После каждой поправки — один вопрос: **есть ли этот случай в
`lessons.md`?**

- **Есть** — в поправке сослаться на номер. Тот же агент повторил урок
  дважды — строка в `capabilities.md` этого агента (⚠️ с номером урока)
  и сказать владельцу.
- **Нет** — новый урок `У-NN` в конец `lessons.md` (формат — в начале
  файла). С этого момента он вставляется **текстом** в каждое поручение
  всем агентам (п. 3), пока PR с уроком не смёржен.

Урок в `main` — через PR: ветка `pcd/lessons-<дата>`, только
`docs/pc-agents/lessons.md` и `capabilities.md`; копить уроки за день в
одном PR. Сборку Vercel `docs/` не запускают. Проверяющий смотрит PR
уроков первым и превращает урок в проверку скриптом, где это можно
(`agent-check`, `check-city`) — тогда урок ловится сам, без диспетчера.

**Эскалация:**

| Случай | Что делать |
|---|---|
| 1-я поправка по задаче | поправка, урок |
| 2-я на ту же ошибку у агента | поправка, ⚠️ в `capabilities.md`, сказать владельцу |
| 3 поправки по одной задаче | остановить задачу, вопрос в PR, сказать владельцу |
| ошибка среды (браузер, диск, токен, вход в Google) | не поправка: строка в `capabilities.md`, «Среда»; сказать владельцу |

## 7. Лимиты и застревания

- **Лимит** — в логе `quota`, `rate limit`, `429`, `RESOURCE_EXHAUSTED`,
  «limit reached». Время снятия — из сообщения, иначе «через 5 часов».
  Его задачу посреди куска не передавать (ветка его). Другому агенту —
  следующий свободный пункт по п. 2. Отзывы и Maps — только агенту со
  сданным экзаменом.
- **Застрял** — нет коммитов больше часа и `agy` не работает: один
  перезапуск с тем же поручением и строкой «продолжи с последнего
  коммита»; повторилось — владельцу.

## 8. Заход: что делать за один запуск

1. `git pull` в `D:\docker\shop`. Читать строки «Сейчас:» в `tasks/pc-*.md` и `tasks/pcN-*.md`,
   не файлы целиком.
2. `docker ps`; у каждого `agyN` — работает ли `agy`, хвост лога, блок ИТОГ.
3. Новые PR: `agent-check` → OK — назначить напарника; FAIL — поправка.
4. Свободным агентам — работу по п. 2.
5. Обновить `D:\docker\status.md`:
   `контейнер | задача | ветка | этап конвейера | с какого времени`.
6. Новые уроки — в `lessons.md` (PR `pcd/lessons-<дата>`).
7. Отчёт владельцу:

```
| контейнер | задача | этап | PR |
поправки: <агент — что — урок>
новые уроки: У-NN …
нужно от владельца: <мерж PR …, вход в Google …>
```

## 9. Экономия

- Модель — любая, в том числе Opus (владелец, 2026-10-01). Экономия — за
  счёт того, что диспетчер не делает чужую работу.
- Данные и диффы целиком не читать: `agent-check`, строки «Сейчас:»,
  хвост лога, блок ИТОГ.
- Заход закончился — выход, сессию не держать.

## 10. Чего не делает никогда

- Не собирает карту, сайты, тексты — даже «пока все заняты».
- Не правит данные и код агентов, не пушит в их ветки.
- Не меняет `tasks/` (задачи пишет проверяющий, раздаёт — диспетчер),
  `quality.md`, `AGENTS.md`, скрипты.
- Не мержит, не создаёт и не удаляет контейнеры, не ставит автозапуск,
  не трогает токены — владелец (`AGENTS.md`, «Критическая
  инфраструктура»).
