# Конвейер нового города: Antigravity на карте и на сайтах, параллельно

Решение владельца (2026-10-01): каждые 10 мест с карты сразу уходят на
сайты, все агенты работают одновременно. Проход Google Maps делает
Antigravity, сдавший экзамен (`maps-exam.md`); CLI на ПК — только
надзор (`dispatcher.md`).

```
картограф (Antigravity, экзамен сдан): [карта 1–10] [карта 11–20] [карта 21–30] ...
                                            │             │             │
agy1:                                       └─[сайты 1–10]              │
agy2:                                       └─[сверка 5 из 1–10]        │
agy3:                                                     └─[сайты 11–20]
...
```

## Кто что делает

- **Картограф** — Antigravity с двумя PASS экзамена по Maps (сейчас
  контейнер ПК с входом в Google, без экзамена — первая партия пилотом). Собирает
  `candidates.csv` кусками по 10 строк, формат — `add-city.md`, «Партии».
  Один картограф на город: Google Maps не любит много запросов с одного
  адреса.
- **Сайты** — любой Antigravity: места куска по `add-city.md`, столбцы
  Maps копирует из строк картографа.
- **Сверка карты** — другой Antigravity, не картограф этого куска: вслепую
  собирает 5 случайных мест куска (как экзамен), проверка —
  `npx tsx scripts/maps-exam.ts <город> <файл сверки>`. FAIL — кусок
  карты проверяется весь заново, картограф получает «Ревью».
- **Диспетчер (CLI на ПК)** — раздаёт куски, следит за лимитами, ничего
  не собирает сам.

## Порядок

1. Город — только из бэклога и только от 500 тысяч жителей
   (`AGENTS.md`, «Проект»). Файл задачи — `<префикс картографа>-city-<slug>.md`.
2. Картограф: ветка `<префикс>/<slug>-00-maps` от `city/<slug>` (ветку
   города создаёт он от свежего `main`, если её нет). После каждых 10
   строк — коммит; **push — не чаще раза на 3 куска** (владелец, 2026-10-05,
   «по 3 куска хотя бы за 1 пуш»; сообщение диспетчеру «куски NN–MM
   готовы» — после push). Исключение — пилот (первый PR задачи, один
   кусок) и последний неполный набор в конце партии.
3. Диспетчер сразу отдаёт кусок: сайты — одному свободному контейнеру,
   сверку 5 мест карты — другому (сверка карты вслепую остаётся). Ветка сайтов растёт от ветки картографа
   («стопка», `AGENTS.md`, шаг 3); PR — в `city/<slug>`.
4. Нет свободного контейнера — кусок ждёт в очереди. Диспетчер сам его не
   делает.
5. Карта пройдена — картограф открывает PR `…-00-maps` в `city/<slug>`
   с результатами сверок. Проверяющий смотрит его первым, потом PR
   кусков по порядку. Мержит владелец.

## Проверка без напарника: ворота, скрипты и выборка

Решение владельца (2026-10-02) **заменяет** взаимную проверку 2026-10-01.
Проверять каждый PR вторым агентом не масштабируется: для города в
тысячи мест (Нью-Йорк) это не выполнить, даже с 20 агентами. Теперь:

1. **Место должно пройти с первого раза.** Агент пишет только то, на что
   есть цитата со страницы (`quality.md`, правило 8): значение без
   цитаты — пустое поле и `none (…)`. Место без сайта — только строка
   из `candidates.csv`. Перед работой — 10 строк «не делай» из
   `dont.md` (диспетчер вставляет их в каждое поручение; полный текст — `lessons.md`).
2. **Ворота и скрипты — бесплатные, обязательные.** Агент открывает PR,
   только когда зелёные: `npm run gate`, `check-city`, `verify-city`,
   `agent-check`, `sanity` (ниже). Это код, он не тратит лимит агентов.
3. **`npm run sanity -- <город|all>`** — проверка адекватности всего
   каталога без агента и без сети: выдуманные телефоны (123456…,
   111111…), координаты вне города, один адрес и название у двух мест,
   рейтинг вне 1–5, плохие часы, кривые e-mail и сайт, телефон
   у двух разных мест. FAIL — PR не открывать; WARN — смотрит аудитор.
4. **Облачный проверяющий** мержит PR, когда зелёные все ворота и
   выборочная перепроверка 2–3 значений с сайтов прошла. Проверки
   напарника больше нет и она не нужна для мержа. `city/*` → `main` —
   по-прежнему только владелец.
5. **Аудитор — один агент, выборка.** Раз в неделю (и перед тем, как
   `city/*` уходит в `main`) берёт случайные 5% мест города (не меньше
   10), сверяет каждое по сайтам и, где нужно, по Google Maps, ставит в
   `data/cities/<город>/audit.csv` строку «слаг, дата, результат»
   и больше к этому месту не возвращается. Допустимый брак — как в
   `maps-exam.ts`: не больше 2% неверных значений. Выше — кусок или
   город проверяется целиком, автору «Ревью».
6. **Уроки.** Каждая найденная ошибка — урок в `lessons.md` и, где
   можно, проверка в `sanity`/`check-city`. Скрипты растут, ручная
   проверка сжимается.

Напарник остаётся по запросу владельца или проверяющего для одного
конкретного PR (спорный случай), но не по умолчанию. Файлы
`board-from-dispatcher.md` и «Проверка напарника (ПК N)» в старых PR —
история.

## Город готов: сдача и мерж (владелец, 2026-10-02)

Цель: CLI на ПК (диспетчер) и агенты доводят город до конца сами, а
оркестратор мержит `city/<город>` → `main` после быстрой проверки.

**Условия сдачи** (диспетчер проверяет все, потом открывает сборный PR
`city/<город>` → `main`):
1. Все куски карты, мест, цен и отзывов в `city/<город>`, у каждого
   `GATE PASS`; пилоты каждой задачи приняты (`board.md`).
2. `cd website && npm run ready-city -- <город>` — все ворота PASS (код 0).
   Отчёт целиком — в описание PR.
3. **Выборка — до PR, сам диспетчер:** 2 места из каждой категории из
   отчёта (`--per=2`): страница на сайте, сайт места, Google Maps;
   значения и 1–2 цитаты верны; у мест со сводкой — 2–3 записи ленты
   против Google (контейнер с входом). Галочки `[ ] проверено` в PR.
   Одна ошибка — «Поправка» агенту и новая выборка (`--seed=<другой>`).
4. Города нового **языка** — только когда язык подключён в коде
   (`docs/playbooks/add-language.md`, `npm run check-language`, когда
   появится); без этого город в `main` не идёт.
5. Нет открытых PR партий в `city/<город>`; `city/<город>` слита с
   свежим `main`.

**Проверки приносит диспетчер (с 2026-10-10).** К сборному PR диспетчер
прикладывает: вывод `ready-city` со своим `--seed`; **`verify-city`,
прогнанный на ПК** (из облака многие сайты отвечают 403 — шум, поэтому
«официальный» прогон его); отметку выборки (2 места на категорию с
Google, у мест со сводкой — 2–3 записи ленты). Для городов, уже
имеющих `verify-city` NOT VERIFIED на `main`, достаточно «новых FAIL нет».

**Мерж.** Оркестратор (облачная сессия Claude Code) запускает на ветке
быстрые `check-city` и `sanity` (облако), сверяет приложенные
`ready-city`/`verify-city` с `main` («новых FAIL-строк нет»), смотрит
1 место из каждой категории из отчёта и мержит PR. Красные ворота, непройденная выборка
или чужой открытый вопрос — не мержить, написать в PR. Город уходит в
`main` **одним PR**; мерж-коммит — с `[deploy]` в заголовке (выкладка сразу
после каждого города, владелец 2026-10-10), после мержа оркестратор
проверяет выкладку (если коннектор Vercel подключён — через него; иначе диспетчер
открывает сайт города и сообщает на доске) и пишет владельцу отчёт.

## Ограничения

- Порядок мест — порядок, в котором их собрал картограф.
- **Сборки Vercel.** Каждый push ветки с `data/` запускает сборку
  предпросмотра, у бесплатного тарифа дневной лимит. Решение — не
  собирать ветки агентов (`pc*/*`, `city/*`): это настройка
  Vercel, решает владелец. До этого — **не меньше трёх кусков на один
  push** (владелец, 2026-10-05): коммиты остаются по куску со штампом
  ворот, пушится пачка. Диспетчер не вливает `main` в ветки городов и
  стран, которые уже в `main` (каждое вливание — push во все такие ветки).
