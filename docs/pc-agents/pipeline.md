# Конвейер нового города: Antigravity на карте и на сайтах, параллельно

Решение владельца (2026-10-01): каждые 10 мест с карты сразу уходят на
сайты, все агенты работают одновременно. Проход Google Maps делает
Antigravity, сдавший экзамен (`maps-exam.md`); CLI на ПК — только
надзор (`dispatcher.md`).

```
картограф (Antigravity, экзамен сдан): [карта 1–10] [карта 11–20] [карта 21–30] ...
                                            │             │             │
agy1:                                       └─[сайты 1–10]              │
agy2:                                       └─[сверка 5 из 1–10]        │
agy3:                                                     └─[сайты 11–20]
...
```

## Кто что делает

- **Картограф** — Antigravity с двумя PASS экзамена по Maps (сейчас
  Mac 2; контейнер ПК — после своего экзамена в Docker). Собирает
  `candidates.csv` кусками по 10 строк, формат — `add-city.md`, «Партии».
  Один картограф на город: Google Maps не любит много запросов с одного
  адреса.
- **Сайты** — любой Antigravity: места куска по `add-city.md`, столбцы
  Maps копирует из строк картографа.
- **Сверка карты** — другой Antigravity, не картограф этого куска: вслепую
  собирает 5 случайных мест куска (как экзамен), проверка —
  `npx tsx scripts/maps-exam.ts <город> <файл сверки>`. FAIL — кусок
  карты проверяется весь заново, картограф получает «Ревью».
- **Диспетчер (CLI на ПК)** — раздаёт куски, следит за лимитами, ничего
  не собирает сам.

## Порядок

1. Город — только из бэклога и только от 500 тысяч жителей
   (`AGENTS.md`, «Проект»). Файл задачи — `<префикс картографа>-city-<slug>.md`.
2. Картограф: ветка `<префикс>/<slug>-00-maps` от `city/<slug>` (ветку
   города создаёт он от свежего `main`, если её нет). После каждых 10
   строк — коммит, push, сообщение диспетчеру «кусок NN готов».
3. Диспетчер сразу отдаёт кусок: сайты — одному свободному контейнеру,
   сверку 5 мест — другому. Ветка сайтов растёт от ветки картографа
   («стопка», `AGENTS.md`, шаг 3); PR — в `city/<slug>`.
4. Нет свободного контейнера — кусок ждёт в очереди. Диспетчер сам его не
   делает.
5. Карта пройдена — картограф открывает PR `…-00-maps` в `city/<slug>`
   с результатами сверок. Проверяющий смотрит его первым, потом PR
   кусков по порядку. Мержит владелец.

## Ограничения

- Порядок мест — порядок, в котором их собрал картограф.
- **Сборки Vercel.** Каждый push ветки с `data/` запускает сборку
  предпросмотра, у бесплатного тарифа дневной лимит. Решение — не
  собирать ветки агентов (`pc*/*`, `mac2/*`, `city/*`): это настройка
  Vercel, решает владелец. До этого — не больше одного push на кусок.
