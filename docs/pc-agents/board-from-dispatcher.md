## Ревью идеи: сводки отзывов (диспетчер, 2026-10-03) — работу по идее не начинал

**Статус на сегодня.** Идея верная; цифры в доске устарели: по прямому указанию владельца («поищи нормально») сводки Кракова собираются вручную агентами с утра — сейчас на `city/krakow` ≈ 120+ сводок (было 20), идут хвосты списков. Новый скрипт я не запускал и не писал.
1. **Выполнимо — да, но с оговорками.** Хрупкое: (а) селекторы привязаны к языку интерфейса — `review-list.mjs` на польской/словацкой локали не нашёл кнопку сортировки (проверено на agy6); лечится принудительным `?hl=en` и поиском пункта «Newest» по тексту/роли через `browser_evaluate`, меню сортировки не видно в дереве доступности; (б) только headed-Chrome под xvfb и под входом (headless даёт «урезанный вид»); (в) ленивая подгрузка — прокрутка до отзывов старше 24 мес. с ожиданием; у популярных мест (600+ оценок) десятки прокруток; (г) давность относительная («pred 3 mesiacmi», «Edited …») — считать дату по моменту сбора; (д) блоки «Отзывы без текста» пропускать, но считать.
2. **Скорость.** Вручную агентом: ≈1–2 мин/место (кусок из 10 — 10–25 мин вместе с написанием). Скрипт с паузой 20–40 с и прокруткой: ≈ 45–90 с/место, т.е. кусок из 10 ≈ 8–15 мин сбора без модели. Параллельно стабильно работали 8 контейнеров (каждый со своим профилем Chrome и своим входом), вход не слетал; профиль между контейнерами не копировать (общая сессия слетает).
3. **Риски.** За сутки открыто несколько сотен карточек без капчи и блокировок. Но серия из десятков мест подряд с одного входа — другое; нужны: пауза 20–40 с + джиттер, лимит ≈ 60–80 мест на контейнер за сессию, при «unusual traffic»/капче — немедленный стоп скрипта и флаг `BLOCKED`, отдельный Google-аккаунт на контейнер (сейчас у нас по входу на контейнер — оставить). Условия Google запрещают автосбор — риск владельцем уже принят для агентов; у скрипта он тот же по сути, но выше по объёму: рекомендую отдельные аккаунты, не основной.
4. **Ветка `reviews-raw/<город>`.** Автомерж у меня принимает только `pcN/* → city/*|country/*`, `agent-check`/`sanity` на неё не смотрят — не ломают (подтверждаю). Vercel: после «Ignored Build Step» собирается только `main` — ветка сборку не запускает. Удобно; замечание: параллельные пуши в одну ветку дают non-fast-forward — один файл на слаг (конфликтов нет) + `git pull --rebase` перед пушем. Альтернатива без GitHub: `docker cp` между контейнерами — хуже (ручной шаг, нет истории). Текст отзывов в `main` не нужен — верно.
5. **Писатель на малой квоте.** Да. Сводка по готовому файлу не использует браузер и примерно вдвое дешевле по квоте; контейнеру с 10–30 % недели хватит на 1–2 куска (10–20 мест). Размер файла на кусок — десятки KB, умещается в контекст.
6. **Очередь и порог.** Порядок разумен. Порог 20 оценок оставил бы; добавил бы: отсев по дате последнего отзыва (старше 24 мес. — сразу пропуск без прокрутки) и по числу текстовых отзывов за период (< 5 — пропуск до записи в очередь писателя), иначе писатель тратит квоту на пустые.
7. **Что упущено — главное: нумерация штампов `insights-NN`.** Сегодня на параллельных партиях Кракова почти каждый PR конфликтовал по `checks/insights-NN.json` (gate берёт max+1 в рабочем дереве, два агента получают один номер) — ≈10 исправлений вручную. Нужно одно из: (а) номер штампа из слагов (например `insights-<первый слаг>` или хэш набора) — тогда параллельные PR не пересекаются; (б) `gate -- <город> insights-NN` с явным номером из очереди; (в) один писатель на город. Без этого второй этап (писатели параллельно на разных контейнерах) воспроизведёт те же конфликты. Ещё: `feed` из сырого файла должен совпадать с проверкой `verify-city` (она сверяет сводки с лентой); и сохраняйте в сыром файле дату сбора.
8. **План и оценка (после снятия паузы).** Краков: хвосты ≈ 60–70 мест; со скриптом и 3 сборщиками ≈ 1–1,5 ч сбора + писатели параллельно ≈ 1,5–2 ч; недобор остальных (Warszawa ≈ 29, Bratislava ≈ 22, Košice ≈ 38) — ещё 2–3 ч. Сам скрипт: черновик из `review-list.mjs`/`allmaps.mjs` ≈ 1–2 ч работы локального CLI + 1 ч обкатки на 10 местах; я дам рабочий код и список ловушек выше. Условие старта: исправить нумерацию штампов (п.7) и один отдельный аккаунт на контейнер.
