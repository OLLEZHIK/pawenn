# Шаблон задачи для исполнителя

**Кому:** тому, кто ставит задачи (оркестратор, «левая» и «правая
рука»). Исполнитель этот файл не читает — он читает готовую задачу.
Почему задача устроена так — `docs/playbooks/quality.md`, §5 и
правила 8–9.

Правила постановки (владелец, 2026-09-28):

- **Маленькая партия.** До 15 мест одной категории; сводки отзывов — до
  10 мест (при длинной ленте — до 5). Больше — таблица «Партии», по
  ветке и PR на строку. Первая партия — самая маленькая: её ревью
  исправит ошибки, пока они не размножились.
- **Доказательства.** Каждое значение с сайта — цитата в
  `evidence*.csv` (`add-city.md`, раздел 1.4); у сводки отзывов — лента
  `feed` (`review-insights.md`). В «Готово, когда» — `verify-city`
  → `VERIFIED`.
- **Честный пробел и остановка.** Фраза из раздела «Если инструмент не
  работает» ниже — в каждой задаче на данные, без изменений.
- **Только проверяемые требования**, и только те, что уже сработали на
  прошлой задаче того же типа (`quality.md`, §5).

## Шаблон

```markdown
# Задача: <что> — <город / объём>

**Исполнитель:** <Antigravity IDE | Antigravity (Mac) | Antigravity (Desktop / Hub) | Claude Code CLI>
**Роль:** <Data agent | Content agent>
**Тип:** <новый город | исправление данных | сводки отзывов>, партии по <15 | 10> мест.
**Ветка PR:** <`city/<slug>` для нового города | `main`>
**Зависимости:** <нет | tasks/…>

<Зачем, 2–4 строки: решение владельца и дата.>

Перед работой — `docs/playbooks/quality.md` и <плейбук>.

## Партии

Одна сессия — одна строка. Брать первую строку без ветки, если PR
предыдущей смёржен. Строки «добавит проверяющий» не заполнять самому.

| # | Что | Ветка |
|---|---|---|
| 0 | <…> | `<префикс>/<slug>-00-<что>` |
| 1 | <категория, места 1–15 из candidates.csv> | `<префикс>/<slug>-01-<категория>` |
| … | добавит проверяющий после партии 0 | |

## Что сделать в каждой партии

<Шаги. Формат файлов и колонок — ссылкой на плейбук, пример строки.>

К каждому значению с сайта — строка в `evidence-<NN>-<категория>.csv`:
цитата со страницы как есть, ссылка на эту страницу
(`add-city.md`, раздел 1.4).

## Если инструмент не работает

Не открылся сайт или Google Maps, нет данных — поле пустое, в `notes`
`<поле>: none (<где смотрел, что не открылось>)`. Это засчитывается,
`check-city` пропускает. Если так у трети мест партии и больше — не
собирать дальше: открыть PR с тем, что есть, и описать проблему в
разделе `## Открытый вопрос`. Сдать меньше мест с объяснением —
нормально; возврат PR бывает за выдумку, не за честный пробел.

## Чего не делать

- Не выдумывать и не «оценивать» (quality.md, правила 1, 7).
- <Известные ошибки этого типа работы из quality.md §1, с номерами PR.>
- Не трогать файлы вне задачи (код сайта, другие города, прошлые партии).

## Готово, когда (для каждой партии)

- **PR открыт** в <ветку PR>, заголовок `<…> — партия <N>`.
- `cd website && npm run check-city -- <slug>` → `READY` и
  `npm run verify-city -- <slug>` → `VERIFIED`, вывод обоих целиком в PR.
- <Таблица / число / файл — только проверяемое.>
- Самопроверка `quality.md` (§2) в PR.
```
