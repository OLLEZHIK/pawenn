# Как добавить язык сайта

Новый город на уже поддерживаемом языке — это только данные
(`docs/playbooks/add-city.md`). Новый **язык** — разовая работа с
кодом, после неё все города на этом языке снова добавляются только
данными. Пример ниже — немецкий (`de`) для Вены.

Утверждено владельцем 2026-09-26.

## 0. Когда добавлять язык

- **Только вместе с первым городом на этом языке**, не заранее
  (`docs/growth-strategy.md` §0: не делаем работу, которая пока
  никому не нужна). Английский есть всегда, у каждого города.
- У города **один местный язык** (`_local` в данных). Город с двумя
  местными языками (Швейцария, Бельгия) — отдельная доработка, когда
  до такого города дойдёт.

## 1. Порядок работ — строго по шагам

| Шаг | Что | Кто | Результат |
|---|---|---|---|
| 1 | Карта ключевых слов языка: как люди ищут категории, услуги из цен и признаки | Antigravity | `docs/seo/keywords/<locale>.md` по методике `docs/seo/keywords/README.md` |
| 2 | Перевод словаря интерфейса и подписей | Antigravity | `website/lib/dictionaries/<locale>.ts` и подписи (раздел 2, пп. 2, 4) |
| 3 | Подключение языка в коде, адреса страниц из шага 1, проверка в браузере | Сессия Claude Code (CLI, «правая» или «левая рука») | PR по разделу 2 и 4 |
| 4 | Первый город на этом языке | Antigravity | `docs/playbooks/add-city.md` |

**Адреса страниц (слаги) выбираются в шаге 3 по карте из шага 1 и
после запуска не меняются**: слаг — это адрес в поиске.

## 2. Что поменять в коде

TypeScript сам показывает, что ещё не переведено: после п. 1 `npx tsc
--noEmit` выдаёт ошибку в каждом месте, где не хватает нового языка.

1. **`website/lib/locales.ts`:**
   - `LOCALES` — добавить `"de"`;
   - `DATE_LOCALE` — `de: "de-AT"` (или `de-DE`): формат дат и правила
     множественного числа;
   - `COUNTRY_LANGUAGE` — страны, где это язык по умолчанию
     (`AT: ["de"]`); у страны с несколькими языками — все, первый по
     умолчанию. По нему корень `/` выбирает язык посетителя.

   Префикс `/de/` в `proxy.ts` и страница 404 подхватят язык сами.
2. **`website/lib/dictionaries/de.ts`** — скопировать `en.ts` и
   перевести все строки. Тип `Dictionary` не даст пропустить ключ.
   Подключить в `website/lib/i18n.ts` (`DICTIONARIES`).
   - Строки-функции (`(count, where) => …`) переводить целиком, с
     правильными формами слов. Для чисел — `plural("de", n, {one,
     other})`: правила берутся из `Intl.PluralRules`, у чешского и
     польского есть ещё `few` и `many`.
   - «В городе» в словаре не собирать: оно приходит из `in_city` в
     `city.json`.
3. **`website/lib/categories.ts`:**
   - `SLUGS` — адреса категорий (из карты ключевых слов);
   - `LABELS`, `SINGULAR`, `PLURAL`, `BLURBS` — названия;
   - `SEO_TITLE` — заголовок страницы категории по главным запросам
     (как для словацкого: «Strihanie psov a psie salóny»);
   - `BUSINESS_SEGMENT` (`podnik` → `betrieb`), `CITY_SEGMENT`
     (`mesto` → `stadt`).
   - страница места живёт в папке с именем сегмента: скопировать
     `website/app/[lang]/podnik/[slug]/page.tsx` в
     `website/app/[lang]/<сегмент>/[slug]/page.tsx` и поменять в ней
     `SEGMENT` (без папки адрес места — 404).
4. **`website/lib/services.ts`** и **`website/lib/vet.ts`** — подписи
   услуг цен и специализаций ветклиник (названия услуг — тоже по
   карте ключевых слов: «kastrácia fenky», а не «kastrácia suky»).
5. **`website/lib/priceSlugs.ts`** — `PRICES_SEGMENT` (`ceny` →
   `preise`) и `SERVICE_SLUGS` для каждой услуги — адреса страниц цен.
6. **`website/lib/attributePages.ts`** — `SLUGS` страниц признаков
   (`nonstop`, `sobota` → `samstag`, `nedela` → `sonntag`, экзоты,
   выезд) — по карте ключевых слов.
7. **`website/lib/seo.ts`** — `OG_LOCALE` (`de: "de_AT"`) для превью
   ссылок.
8. **`website/components/LanguageSwitch.tsx`** — `NAMES`, название
   языка на нём самом (`Deutsch`).

Переключатель языка (`lib/localeSwitch.ts`) сам переводит адреса
категорий, цен и признаков — отдельно его не трогать.

Страницы помощи и юридические тексты — **только на английском**, для
всех языков, без пометки языка (решение владельца 2026-09-26). Их не
переводят.

## 3. Что на языке города в данных

- `city.json`: `"locale": "de"`, `"locales": ["de"]`, `"in_city":
  {"en": "in Vienna", "de": "in Wien"}`; в `districts.geojson` — `in`
  для районов («im 1. Bezirk»).
- `businesses.csv`: `short_description_local`, `description_local`,
  `emergency_note_local` (`docs/card-spec.md`).
- `prices.csv`: `note_local`.
- `review-insights/*.json`: тексты под ключом кода языка
  (`{ "en": …, "de": … }`, `docs/playbooks/review-insights.md`).

Скрипт `check-city` берёт языки города из `city.json` и проверяет
тексты на всех этих языках сам.

## 4. Качество перевода и проверка перед PR

**Перевод:**
- Живой язык, как у местного редактора, а не калька с английского.
- Правильные формы слов: падежи («v Bratislave», «in Wien»), числа
  (`plural`), род. Не уверен в форме — не угадывать, вопрос в PR
  (`docs/playbooks/quality.md`, правило 7).
- Названия категорий, услуг и признаков — словами из карты ключевых
  слов, а не своими.

**Проверка (шаг 3):**
- `npx tsc --noEmit` и `npx eslint` без ошибок.
- На тестовой базе с городом на новом языке (`website/prisma/fixtures/`):
  - `/de/`, `/de/stadt/<город>/`, страница категории, цен, признака и
    карточки места отдают 200;
  - hreflang связывает `de` с английской версией;
  - переключатель языка ведёт на ту же страницу на другом языке;
  - в `sitemap.xml` есть страницы `/de/`;
  - для города без `de` в `locales` страница `/de/...` отдаёт 404.
- Скриншоты главной, хаба города, списка и карточки на телефоне
  (390 px): длинные слова не ломают вёрстку.
- В `docs/seo/README.md` §2.1 дописать слаги нового языка.
- В PR — самопроверка из `docs/playbooks/quality.md` (§2).
