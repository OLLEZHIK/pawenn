# Инструкция: «Что говорят клиенты» — сводка отзывов и FAQ

**Для кого:** исполнитель — Claude Code CLI (`cli-`, `cmac-`; с
2026-09-29 работа с Google Maps только у CLI, `AGENTS.md`,
«Специализация»), любой город. Делается вторым проходом после
`businesses.csv` города (`docs/playbooks/add-city.md`).
Перед работой — `docs/playbooks/quality.md`.

## Зачем

Решение владельца (2026-09-24): на странице места показать, что клиенты
думают о нём за последние полгода — отношение, результат, цены, запись
и ожидание — и ответы на частые вопросы. Это **уникальный текст на
местном языке**, которого нет больше нигде: для SEO и для ответов
ИИ-ассистентов.

**Главное правило: это не отзывы, а наша сводка отзывов.** Не от лица
клиента, без авторов и своих звёзд. Текст, выданный за отзывы клиентов,
— фейковые отзывы: их запрещает закон ЕС о защите потребителей
(директива Omnibus), и Google наказывает за них весь сайт. Честная
сводка «многие пишут, что…» законна и для SEO ценнее.

## Для каких мест

- Места города с **≥ 20 оценками** Google (`google_rating_count`) и
  **≥ 5 отзывами с текстом** за период ниже. Остальным файл не
  создавать — перечислить в PR с причиной.
- **Период — ступенями (владелец, 2026-09-28; в маленьких городах за
  полгода отзывов мало — в Кошице у 39 из 53 мест меньше 5):**
  1. последние **6 месяцев**; набралось ≥ 5 — сводка за них;
  2. нет — последние **12 месяцев**;
  3. нет — последние **24 месяца**; старше не брать (отзывы трёхлетней
     давности о месте сейчас уже не говорят).
  `period_from` / `period_to` — тот период, что взят на деле: сайт
  пишет его на странице («marec 2025 – september 2026»). Выбирать
  самый короткий из подходящих, не длиннее. В таблице PR — какой
  период взят.
- Места, где и за 24 месяца меньше 5 отзывов с текстом, получают на
  сайте короткий блок без сводки (рейтинг Google, «Все отзывы на
  Google», «Оставить отзыв») — его делает сайт сам, файл не нужен.
- Сначала места с наибольшим числом оценок. Братислава — образец
  (`docs/growth-strategy.md`, раздел 0): полнота не цель, качество — да.

## Файл

`data/cities/<город>/review-insights/<slug>.json`, `slug` — как в
`businesses.csv`. Языки — английский и **каждый язык из `locales`
города** (`city.json`): для Братиславы `en` + `sk`, для Брно `en` + `cs`.

```json
{
  "slug": "veterinarna-ambulancia-kocur",
  "source": "google",
  "google_maps_url": "https://maps.google.com/?cid=...",
  "period_from": "2026-03-26",
  "period_to": "2026-09-26",
  "reviews_in_period": 23,
  "observed_at": "2026-09-26",
  "cards": [
    {
      "topic": "staff",
      "sentiment": "positive",
      "mentions": 14,
      "title": { "en": "…", "sk": "…" },
      "text":  { "en": "…", "sk": "…" }
    }
  ],
  "faq": [
    {
      "q": { "en": "…", "sk": "…" },
      "a": { "en": "…", "sk": "…" },
      "basis": "reviews"
    }
  ],
  "feed": [
    { "ago": "pred 3 týždňami", "months": 0, "stars": 5, "topics": { "staff": "+", "results": "+" } },
    { "ago": "pred 2 mesiacmi", "months": 2, "stars": 2, "topics": { "waiting": "-", "staff": "~" } },
    { "ago": "pred 4 mesiacmi", "months": 4, "stars": 5, "topics": {} }
  ]
}
```

- `google_maps_url` — из столбца `google_maps_url` в `businesses.csv`.
- `cards` — **ровно 3**, три самые обсуждаемые темы из: `staff`
  (отношение, объяснения), `results` (результат лечения/стрижки),
  `prices` (как оценивают цены), `waiting` (запись, ожидание), `place`
  (чистота, парковка, доступность), `communication` (телефон, ответы),
  `animals` (как обращаются с животными).
  `sentiment`: `positive` / `mixed` / `negative`. `mentions` — сколько
  **разных** отзывов за период говорят об этой теме, **не меньше 3**.
- `title` — 3–6 слов. `text` — 2–4 предложения, **250–450 символов**
  на каждом языке; по смыслу языки одинаковые.
- `faq` — **3–6** вопросов, которые реально задаёт владелец питомца:
  запись, ожидание, парковка, экзоты, английский, оплата картой,
  неотложка. `basis`: `reviews`, `website` или `both`. Нет надёжного
  ответа — вопрос не включать.

### Лента `feed` — доказательство чтения (владелец, 2026-09-28)

Сводка строится из ленты отзывов, и лента лежит в том же файле. Урок
PR #182 (Варшава): у места с двумя критическими отзывами из трёх
последних все карточки были положительными, у 63 мест — одна форма.

- **Каждый отзыв с текстом за период** — одна запись, **сверху самые
  новые** (сортировка «Новые» / «Najnovšie» / «Najnowsze»). Отзывы без
  текста не записывать. Число записей = `reviews_in_period`.
- `ago` — как Google пишет дату, **копией**: «pred 3 mesiacmi», «a year
  ago», «2 miesiące temu». `months` — число из неё: дни и недели → `0`,
  «месяц назад» → `1`, «N месяцев» → `N`, «год назад» → `12`, «N лет» →
  `12 × N`. Все `months` меньше длины периода (6, 12 или 24).
- `stars` — звёзды отзыва, 1–5.
- `topics` — о каких темах из списка карточек (`staff`, `results`,
  `prices`, `waiting`, `place`, `communication`, `animals`) говорит
  отзыв и как: `+` хвалит, `-` критикует, `~` и то и другое. Отзыв ни о
  чём из списка — `{}`. Отзыв на 1–2 звезды без `-` не бывает.
- **Без имён, без текста отзывов** — только дата, звёзды и темы
  (персональные данные и авторское право).
- Из ленты `check-city` **считает** карточки: темы карточек — три самые
  частые; `mentions` — сколько отзывов о теме; `sentiment` — `negative`,
  если `-` больше, чем `+`; `mixed`, если критики (`-` и половина `~`) —
  20 % отзывов о теме и больше; иначе `positive`. Не сходится — сводка
  не принимается. Он же проверяет период ступенями: 5+ отзывов за 6
  месяцев — период 6, не 12.
- Проверяющий открывает ленту 2–3 мест и сверяет первые 10 записей
  (дата и звёзды) с Google — выдуманная лента не совпадёт.
- Правило для файлов с `observed_at` от 2026-09-29; старые сводки не
  переделываются.

**Кусками по 10 сводок с воротами** (владелец, 2026-09-28/29;
`quality.md`, правило 10): 10 файлов → `cd website && npm run gate --
<город>` → `GATE FAIL` — исправить по ленте и снова, `GATE PASS` —
закоммитить вместе со штампом `checks/insights-<NN>.json` → следующие
10. PR — до 3 кусков, первый PR задачи — 1 кусок. У мест с 50+ отзывами
за период лента длинная — кусок можно делать меньше 10.

Эталон тона и формата — 10 файлов пилота в
`data/cities/bratislava/review-insights/`.

## Правила

**Честность**
- Писать обобщением: «Most reviewers…», «Several owners mention…»,
  «Viacerí zákazníci…». **Не** от первого лица, без выдуманных историй,
  имён и цитат.
- Негатив не прятать: 4 жалобы из 20 на ожидание — это карточка
  `mixed`. Одни похвалы при заметной критике — нарушение.
- Цены — только как клиенты их оценивают («primerané», «drahšie,
  ale…»). Суммы — только из официального прайса, не из отзывов.
- Отзывы **не копировать**, даже кусками.
- Только отзывы из выбранного периода (6, 12 или 24 месяца до
  `observed_at`, раздел «Для каких мест»).

**Язык и SEO**
- Сначала текст на языке города, потом английский. Живой язык, как у
  местного редактора, не перевод.
- Тип места и район/город — естественно, **один раз** («veterinár v
  Petržalke»), без повторов ключевых слов.
- Без превосходных степеней от себя («najlepší», «best»); только если
  это мнение большинства, и с атрибуцией («Mnohí ho označujú za…»).

**Сбор**
- **Подготовка — перед каждой партией** (урок PR #197, 2026-09-29):
  открыть карточку одного места партии. Есть вкладка «Opinie» /
  «Recenzie» / «Reviews», и лента прокручивается дальше 5–10 отзывов —
  можно работать. Внизу «Korzystasz z ograniczonego widoku Map Google» /
  «limited view» и отзывов нет — это браузер без входа в Google: не
  начинать, написать в PR `## Открытый вопрос`. Задачи на сводки ставятся
  только исполнителю, у которого лента открывается.
- Читать отзывы вручную на карточке Google Maps, сортировка «Новые».
  Без скрейперов.
- Никаких персональных данных авторов.

## Проверка и PR

- `cd website && npm run check-city -- <город>` → `READY`. Скрипт
  проверяет формат каждого файла: 3 карточки, 3–6 FAQ, все языки
  города, 250–450 символов, `mentions` ≥ 3, slug = файл = место, и
  карточки против ленты `feed` (раздел «Лента»).
- В описании PR:
  - самопроверка из `docs/playbooks/quality.md` (§2);
  - таблица: место, `reviews_in_period`, темы карточек с `sentiment`,
    число FAQ (даты и звёзды — уже в `feed`, в PR их не переписывать);
  - места без файла и причина (меньше 20 оценок, меньше 5 отзывов с
    текстом за 24 месяца, нет карточки Google).

**Что ревьюер возвращает сразу (урок PR #156, Кошице, 2026-09-27):**
- `reviews_in_period` не сходится с картой: у места сотни оценок, а за
  полгода «5–8 отзывов». В таблице PR у каждого места — число отзывов с
  текстом за период, как его показала карта (сортировка «Новые»).
- `mentions` по шаблону (5/4/3 у всех мест): это число реально
  посчитанных отзывов по теме, а не «все, все минус один…».
- Факт, которого нет у места: другой адрес, район, улица. Адрес и район
  в тексте — только из `businesses.csv`.
- Текст добит до 250 символов одной и той же фразой («during their
  visits in Košice», «počas každej návštevy»). Не хватает мысли для
  250 символов — значит, по теме мало отзывов: взять другую тему или
  не делать сводку.
- Отзывы не открываются (без входа Google иногда показывает урезанную
  карточку: лента обрывается на 4–5 отзывах, хотя оценок сотни — это
  потолок, а не реальное число, PR #156; тогда нужен вход) — сводку не писать,
  место в список «без сводки» с причиной.
