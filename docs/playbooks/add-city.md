# Инструкция: добавить город (для любого исполнителя)

Инструкция общая для Antigravity, IDE и Mac: префикс ветки — свой
(`antigravity/`, `mac/`), остальное одинаково. **Город собирается
партиями** (владелец, 2026-09-28): партия 0 — список кандидатов, дальше
партии до 15 мест одной категории, каждая — своя сессия и свой PR в
ветку города `city/<slug>`. Порядок — раздел «Партии». Разные города не
пересекаются по файлам, их можно вести параллельно с разных аккаунтов.

## Промпт для запуска (владелец копирует)

Задачу города ставит проверяющий: файл `tasks/<префикс>-city-<slug>.md`
с таблицей «Партии». Промпт один на все партии:

```
Ты — <исполнитель>, проект pawenn (репозиторий OLLEZHIK/shop).
Прочитай AGENTS.md, docs/playbooks/quality.md и docs/playbooks/add-city.md.
Проверь задачу: возьми следующую партию из таблицы «Партии» своего
файла в tasks/ и сделай только её. Перед PR: npm run check-city -- <slug>
→ READY и npm run verify-city -- <slug> → VERIFIED. PR — в ветку
city/<slug>, не в main. После ревью — только новые коммиты, без force-push.
```

Язык города должен быть на сайте (`docs/playbooks/add-language.md`):
нет языка — сначала шаги языка, город идёт вместе с ним.

---

## 0. Перед началом

- Прочитать `AGENTS.md` и `docs/playbooks/quality.md` (стандарт
  качества и самопроверка для PR). Главное правило для этой работы:
  **факты не выдумывать.** Нет данных — поле пустое, причина в `notes`.
- **Город — шаблон, а не цель** (владелец, 2026-09-26,
  `docs/growth-strategy.md` §0): нужна достаточная, честная полнота по
  правилам ниже, без доводки ради одного города.
- Проверить, что ветки `*/city-<slug>` (любой префикс) ещё нет на GitHub.
  Если есть — город уже в работе у другой сессии: остановиться и
  сообщить об этом.
- **База данных не нужна.** Эта работа — только файлы. Сайт, `prisma`,
  `npm run db:seed` не запускать. Боевая база — Neon, локально
  работать с ней нельзя (`docs/database.md`).
- `<slug>` города — название латиницей без диакритики, в нижнем
  регистре, пробелы → дефис: `Košice` → `kosice`, `Banská Bystrica` →
  `banska-bystrica`.

## 1. Результат: какие файлы создать

```
data/cities/<slug>/city.json                  город (партия 0)
data/cities/<slug>/candidates.csv             все найденные места, без деталей (партия 0)
data/cities/<slug>/businesses-<NN>-<кат>.csv  кусок NN: до 10 мест
data/cities/<slug>/evidence-<NN>-<кат>.csv    цитаты-доказательства куска NN (раздел 1.4)
data/cities/<slug>/checks/<NN>-<кат>.json     штамп ворот куска (пишет npm run gate)
data/cities/<slug>/prices.csv                 цены на 6 главных услуг (docs/card-spec.md, «Цены»)
data/cities/<slug>/review-insights/           «что говорят клиенты», файл на заведение
website/public/logos/<slug>/                  логотипы (если нашлись)
```

Больше ничего не менять: не трогать код сайта и чужие папки городов.

### 1.1 `city.json`

```json
{
  "name": "Košice",
  "slug": "kosice",
  "country": "SK",
  "locale": "sk",
  "locales": ["sk"],
  "timezone": "Europe/Bratislava",
  "currency": "EUR",
  "in_city": { "en": "in Košice", "sk": "v Košiciach" },
  "lat": 48.7164,
  "lng": 21.2611,
  "sources": ["https://sk.wikipedia.org/wiki/Košice"],
  "observed_at": "2026-09-25"
}
```

- `country` — код страны ISO из двух букв (`SK`, `CZ`, `AT`, `US` …).
- `locale` — главный язык города (`sk`, `cs`, `de` …).
- `locales` — все местные языки, главный первым. Английский сайт
  добавляет сам, его сюда не писать. Для англоязычного города
  (США, Великобритания, Ирландия) — пустой список `[]`, `locale` — `"en"`.
- `timezone` — **обязательно**, часовой пояс города по базе IANA
  (`Europe/Vienna`, `America/New_York`). Без него seed не загрузит город.
- `currency` — **обязательно**, валюта цен в `prices.csv` (`EUR`, `CZK`,
  `PLN`, `USD` …). Сайт пишет цены и знаки уровня цены в этой валюте сам
  («40 zł», «zł zł»); в `prices.csv` колонку можно оставить пустой.
- `in_city` — «в городе» на английском и на каждом языке из `locales`,
  с правильным падежом: `v Košiciach`, а не `v Košice`. Если не знаешь
  правильную форму — оставь только `en`.
- `lat`/`lng` — центр города.
- **Районы не собираем** (решение владельца, 2026-09-25). Район
  заведения сайт определяет сам по координатам и границам районов из
  OpenStreetMap. Поэтому точные `lat`/`lng` у каждого заведения важны.
- **Границы районов — `districts.geojson`** (готовит тот, кто загружает
  город). У каждого района в `properties`: `name`, `slug` и `in` —
  «в районе» на английском и языках города, с правильным падежом:
  `"in": {"en": "in Petržalka", "sk": "v Petržalke"}`. Из него сайт
  пишет «Veterinárne ambulancie v Petržalke, Bratislava». Без `in` —
  «– Petržalka, Bratislava» (звучит машинно). Формы не генерировать:
  не уверен — оставь только `en`.

### 1.2 `businesses.csv`

**Что собирать для каждого заведения, зачем и на каком языке — в
`docs/card-spec.md` (стандарт карточки).** Ниже — формат файла.

Первая строка — ровно этот заголовок (порядок столбцов важен):

```
category,name,slug,address,lat,lng,phone,email,website,instagram,facebook,short_description,short_description_local,description,description_local,opening_hours,hours_source_url,hours_observed_at,emergency_24_7,emergency_note,emergency_note_local,home_visits,specialties,languages_spoken,facts,photo_urls,google_place_id,google_maps_url,google_rating,google_rating_count,rating_observed_at,logo_file,source_url,observed_at,closed,notes
```

Столбцы `emergency_24_7`, `emergency_note`, `emergency_note_local`,
`home_visits`, `specialties` заполняются только у `VET_CLINIC`, у
остальных пустые. `languages_spoken` у ветклиник обязателен (или пометка
`languages: none (...)` в `notes`). `photo_urls` и `animals` не собирать —
столбцы остаются пустыми (`docs/card-spec.md`, раздел 10).
`emergency_24_7=yes` — только по правилу «Nonstop 24/7» из
`docs/card-spec.md` (раздел 8): заведение само прямо пишет, что
принимает круглосуточно, и часы `24h` все 7 дней. Дежурный телефон,
ночная или выходная неотложка — это `emergency_note` /
`emergency_note_local` (на двух языках), не nonstop.
`check-city` такие ошибки не пропускает.
Столбцы, которых нет в таблице ниже, описаны в `docs/card-spec.md`.

| Столбец | Что | Правила |
|---|---|---|
| `category` | тип заведения | ровно одно из: `GROOMING`, `VET_CLINIC`, `PET_HOTEL`, `DOG_TRAINING`, `PET_SHOP`, `PET_SITTING` |
| `name` | название | как у самого заведения (вывеска или сайт), без «s.r.o.», если его нет в вывеске |
| `address` | адрес | улица, номер, индекс, город: `Hlavná 12, 040 01 Košice` |
| `lat`, `lng` | координаты | 5–7 знаков после точки, **из скопированной ссылки Maps** (числа после `!3d` и `!4d`) или карточки; не округлять и не подбирать «рядом» — `check-city` сверяет с точкой в ссылке (±200 м). Мобильная служба без помещения — пусто и `coords: none (mobile service, no premises)` в `notes`; центр города не ставить |
| `phone` | телефон | в международном формате: `+421 905 123 456` |
| `email` | почта | только публично указанная самим заведением |
| `website` | сайт | официальный сайт или официальная страница в соцсети; `https://…` |
| `short_description` | короткое описание на английском | до 100 символов, своими словами, см. раздел 3 |
| `short_description_local` | то же на языке города | до 100 символов; естественный язык, не дословный перевод |
| `description` | подробное описание на английском | 2–4 предложения своими словами |
| `description_local` | то же на языке города | своими словами, не дословный перевод |
| `google_place_id` | Place ID | `ChIJ…` — в скопированной ссылке после `!19s` (до `?`). **Не** `0x…:0x…` из той же ссылки — это другой номер |
| `google_maps_url` | ссылка на место в Google Maps | **копия из адресной строки** открытой карточки места (`https://www.google.com/maps/place/…/data=!4m7…`). Никогда не составлять. Карточки нет / Maps не открылся — пусто и `maps: none (...)` в `notes` |
| `google_rating` | рейтинг | ровно как на карточке, например `4.7`; пусто, если оценок меньше 5 (и `rating: none (...)` в `notes`) |
| `google_rating_count` | число оценок | целое; пусто, если меньше 5 |
| `rating_observed_at` | дата просмотра рейтинга | `YYYY-MM-DD` |
| `logo_file` | имя файла логотипа | только имя файла в `website/public/logos/<slug>/`, например `vetamin.png`; или пусто |
| `source_url` | главный источник данных | официальный сайт заведения, иначе ссылка на Google Maps |
| `observed_at` | дата сбора | `YYYY-MM-DD` |
| `facts` | «коротко о месте» | коды из `docs/card-spec.md` §9 — только то, что место **прямо пишет**. Факт не на главной странице сайта — ссылка в `notes`: `parking: <URL>`. `appointment_only` — только по прямым словам («len na objednávku», «tylko po umówieniu», «by appointment only»); «можно записаться», «записанные идут первыми» — **не** он |
| `notes` | служебные пометки | что не нашлось и почему, в формате `<поле>: none (<где смотрел>)`; ссылки-доказательства фактов; посетителям не показывается |

Текст с запятыми брать в двойные кавычки. Кодировка UTF-8.

### 1.3 `prices.csv`

Первая строка — ровно этот заголовок (все колонки, даже если пустые):

```
business_slug,price_code,weight_from_kg,weight_to_kg,price_from,price_to,currency,source_url,observed_at,notes,unit,partial,note,note_local
```

Правила — `docs/card-spec.md`, «Цены»: коды только своей категории;
точная цена — в оба поля, «od X» — только `price_from`; `source_url` —
страница прайса, которая открывается; в `notes` — строка прайса как есть.
У места без опубликованного прайса — в `notes` места
`prices: none (<где смотрел>)`, например
`prices: none (site - no cenník page, fb - not posted)`; просто
«not published» не писать.

Где прайсы бывают (Кошице, PR #151): страница «Cenník» в меню; PDF
(университеты, крупные клиники — открыть и искать по разделу нужной
клиники); цены прямо на странице услуги или курса. «Komplet cena»
операции с анализами и лекарствами — больше стандарта: цена как есть и
`note` («incl. blood tests, drugs»). Прайс сети — каждому филиалу, в
`notes` «cenník siete». Операция «od X, bez liečiv» или наркоз
отдельными вариантами — `partial=yes`.

### 1.4 `evidence.csv` — доказательства (владелец, 2026-09-28)

Каждое значение, взятое с сайта или соцсети места, — строка с
**дословной цитатой** со страницы, где оно написано
(`docs/playbooks/quality.md`, правило 8). Файл куска —
`evidence-<NN>-<категория>.csv` рядом с `businesses-<NN>-<категория>.csv`.

```
business_slug,field,quote,source_url,observed_at
vetamin,facts:parking,Parkovanie zdarma priamo pred ambulanciou,https://vetamin.sk/kontakt,2026-09-29
vetamin,opening_hours,Po – Pi: 8:00 – 18:00 So: 9:00 – 12:00,https://vetamin.sk/kontakt,2026-09-29
vetamin,languages:en,Komunikujeme aj v anglickom jazyku,https://vetamin.sk/o-nas,2026-09-29
vetamin,price:vaccination_dog,Vakcinácia psa (komplexná) 32 €,https://vetamin.sk/cennik,2026-09-29
vetamin,description,Sme rodinná ambulancia so zameraním na mačky a exoty,https://vetamin.sk/o-nas,2026-09-29
```

| `field` | Когда нужна цитата |
|---|---|
| `facts:<код>` | каждый код в `facts` |
| `specialties:<код>` | каждая специальность ветклиники |
| `languages:<код>` | каждый язык в `languages_spoken` |
| `emergency_24_7`, `emergency_note`, `home_visits` | если заполнено |
| `opening_hours` | если часы взяты с сайта или соцсети (часы с карточки Google Maps — без цитаты, `hours_source_url` — ссылка Maps) |
| `price:<код>` | каждая строка `prices.csv`: цитата — строка прайса, в ней должна быть цена (или её части, если их сложили) |
| `description` | хотя бы одна цитата с сайта, на которой построено описание (у места без сайта и соцсети — не нужна) |
| `address`, `email`, `closed` | по желанию, если источник не очевиден |

- **Цитата — копия, не пересказ:** выделить на странице и скопировать,
  10–400 символов, на языке страницы. `verify-city` ищет её на странице
  без учёта пробелов и регистра — пересказ не найдётся.
- Цитата должна называть то, что доказывает: для `facts:parking` —
  слово о парковке, для `languages:en` — об английском. `check-city`
  это проверяет.
- `source_url` — **та страница, где цитата**, а не главная. Каталоги —
  не источник.
- Страница из соцсети, PDF, сайт на JavaScript — цитату всё равно
  писать: скрипт их прочесть не может и перечислит, проверяющий откроет
  руками.
- Правило для строк с `observed_at` от 2026-09-29 и для всех строк в
  файлах кусков. Старые данные городов не передоказываются.

## 2. Как собирать (быстрый порядок)

### Партии и куски (владелец, 2026-09-28/29)

Почему: в большой партии к концу сессии данные превращаются в шаблон
и догадки (все описания Кошице и Варшавы — один абзац на категорию; 63
сводки Варшавы «за час»). Маленький кусок проверяется сразу, и ошибка
не размножается.

- **Кусок — 10 мест** одной категории: один файл
  `businesses-<NN>-<категория>.csv` и его `evidence-<NN>-<категория>.csv`.
  `NN` — номер куска в городе по порядку (01, 02, …).
- **После каждого куска — ворота** (`quality.md`, правило 10):

  ```
  цикл по кускам:
    1. собрать 10 мест (строки, цитаты, цены, логотипы)
    2. cd website && npm run gate -- <slug>
    3. GATE FAIL → исправить по списку, заново открыв источник → шаг 2
       (на 3-м круге несошедшееся — пусто и none (...); не работает
       инструмент — стоп, вопрос в PR)
    4. GATE PASS → git commit (кусок + data/cities/<slug>/checks/<NN>-<категория>.json)
    5. следующие 10
  ```

- **Партия = PR = 1–3 куска.** Первый PR задачи — **один кусок** (пилот):
  проверяющий смотрит, правильно ли понята задача, — этого скрипт не
  видит. Дальше — по строкам таблицы, конвейером, без ожидания ревью.

**Ветка города `city/<slug>`** — в ней собирается город; в `main` он
уходит одним PR, когда готовы все партии (одна сборка Vercel, и
посетители не видят полгорода). Её создаёт исполнитель партии 0 от
свежего `main`, если её ещё нет:

```
git fetch origin
git push origin origin/main:refs/heads/city/<slug>
```

Каждая партия: ветка `<префикс>/<slug>-<номер партии>-<категория>` от
свежего `origin/city/<slug>`, PR **в `city/<slug>`**. Мёржит проверяющий; он же
открывает итоговый PR `city/<slug>` → `main`.

**Партия 0 — кандидаты и проход Maps (Claude Code CLI; `AGENTS.md`,
«Специализация», владелец 2026-09-29).** `city.json`,
`districts.geojson` и `data/cities/<slug>/candidates.csv` — список всех
найденных мест всех шести категорий, и у каждого — то, что показывает
его карточка Google Maps (раздел 4):

```
category,name,google_maps_url,google_rating,google_rating_count,address,phone,website,opening_hours,observed_at,notes
VET_CLINIC,Vetamin,https://www.google.com/maps/place/…,4.8,214,"Hlavná 12, 080 01 Prešov",+421 905 123 456,https://vetamin.sk,mo 08:00-18:00; tu 08:00-18:00; we 08:00-18:00; th 08:00-18:00; fr 08:00-18:00; sa closed; su closed,2026-09-29,
```

Всё — **копией с карточки**: ссылка (раздел 4), рейтинг и число оценок
(меньше 5 — оба пусто и `rating: none (...)`), адрес, телефон, сайт,
часы в формате `docs/card-spec.md` §5 (нет на карточке — пусто),
`observed_at` — дата. Нет карточки — пусто и `maps: none (...)`.
Закрытые места не включать. В PR — какие запросы и каталоги
использованы. По этому списку проверяющий режет город на партии и
вписывает их в таблицу «Партии» файла задачи. (Список Кракова —
старого вида, без рейтинга и часов: его места собирает один CLI.)

**Партии 1…n — места (Antigravity, по сайтам).** Те строки
`candidates.csv`, что названы в таблице (например, «VET_CLINIC, места
11–30 по числу оценок — куски 02, 03»), кусками по 10 с воротами после
каждого. Google Maps не открывать: всё, что с карточки, — **копией из
`candidates.csv`**:

| Столбец места | Откуда |
|---|---|
| `google_maps_url`, `google_rating`, `google_rating_count` | из `candidates.csv` как есть |
| `rating_observed_at` | `observed_at` из `candidates.csv` |
| `google_place_id`, `lat`, `lng` | из той же ссылки: после `!19s` (до `?`), после `!3d` и `!4d` |
| `address`, `phone` | с сайта места; на сайте нет — из `candidates.csv` |
| `opening_hours` | с сайта (цитата, `hours_source_url` — страница сайта); на сайте нет — из `candidates.csv`, `hours_source_url` — ссылка Maps, `hours_observed_at` — `observed_at` |
| `maps: none`, `rating: none` в `notes` | из `notes` в `candidates.csv` |

`check-city` сверяет: ссылка, рейтинг, число оценок и часы с
`hours_source_url` на Google Maps — ровно как в `candidates.csv`; иначе
ворота не пройдут. Сайт читает все
`businesses*.csv` города; цены — дописать в `prices.csv`, логотипы — как
обычно. Не трогать куски прошлых партий: правка после ворот снимает
PASS. Партии идут **конвейером** (`AGENTS.md`, шаг 3 самоопределения):
партии 0 и 1 (пилот) ждут ревью, дальше агент не останавливается —
ветка следующей партии от ветки предыдущей, пока та на проверке, не
больше 3 PR на проверке.

**Сводки отзывов** — после того как город в `main`, кусками по 10 с
воротами, PR в `main` (`docs/playbooks/review-insights.md`); делает CLI.

**Если инструмент не работает** (Google Maps в урезанном виде, сайты
не отвечают) — поле пустое и `<поле>: none (<что не открылось>)`; это
засчитывается. У трети мест партии и больше — остановиться, открыть PR
с тем, что есть, и описать проблему в разделе `## Открытый вопрос`
(`quality.md`, правило 9).


Ориентир — **до 100 заведений на город**, но только реально
существующих и работающих. Сколько нашлось, столько и есть: добивать
до 100 сомнительными записями нельзя. В маленьком городе 30–50 — это
нормально.

**Большой город (кандидатов больше 100):** брать в каждой категории
места с наибольшим числом оценок Google, в пропорции как у Братиславы
(ветклиники ≈ половина). В PR — правило отбора и сколько было
кандидатов.

Работать **по категориям, по очереди** (не прыгать между ними):
VET_CLINIC → PET_SHOP → GROOMING → PET_HOTEL → DOG_TRAINING →
PET_SITTING.

**Какими словами искать.** Запросы — те, которыми люди реально ищут на
языке города: главные и вторые варианты из карты ключевых слов
`docs/seo/keywords/<язык>.md` (колонка «Решение»), плюс название
города. Для словацкого, например:

| Категория | Запросы в Google Maps |
|---|---|
| VET_CLINIC | «veterinár <город>», «veterina <город>», «veterinárna pohotovosť <город>» |
| PET_SHOP | «zverimex <город>», «chovateľské potreby <город>»; сети (Super zoo, Fressnapf, Pet Center) — каждый филиал отдельной строкой |
| GROOMING | «strihanie psov <город>», «psí salón <город>» |
| PET_HOTEL | «hotel pre psov <город>», «psí hotel», «hotel pre mačky», «psia škôlka» |
| DOG_TRAINING | «výcvik psov <город>», «cvičisko pre psov», «kynológ» |
| PET_SITTING | «venčenie psov <город>», «stráženie psa <город>» |

Для ветклиник — ещё список членов ветеринарной палаты страны (для SK —
Komora veterinárnych lekárov SR), если он доступен. **Нет карты
ключевых слов для языка города** — сначала её делают
(`docs/seo/keywords/README.md`), и только потом город.

**Откуда брать факты.** Все данные карточки — **только** с
официального сайта или официальной соцсети места, плюс карточка Google
Maps (адрес, часы, рейтинг, ссылка). Каталоги (azet.sk, zzz.sk,
oma.sk, firmy.sk и т.п.) — **только список названий**, чтобы найти
место; данные из них не переносить.

**Проверка полноты.** Закончив категорию, открыть 1–2 каталога этой
категории по городу и сверить со своим списком. Нашлось работающее
место, которого нет, — добавить по обычным правилам. Записать в PR,
какие каталоги сверяли.

**Дубли.** Перед добавлением места искать его в `businesses.csv` по
**телефону**, **адресу** и **сайту**, не только по названию. Одно место —
одна строка. У клиники и её врача часто **две карточки Google** на один
адрес (Slon и «MVDr. …», PR #144) — это одно место: оставить карточку с
большим числом оценок. Адрес пишут по-разному («Ždiarska 5» и «Ždiarska
1442/5») — сверять телефон и точку на карте. `check-city` ловит пары
«одна категория + один сайт + точки ближе 200 м»; если это правда разные
места — в `notes` обеих: `duplicate-check: different place (<чем>)`. Одна фирма с двумя **разными** услугами (ветклиника и
гостиница для кошек) — две строки, это нормально.

Для каждого места: взять список из поиска → открыть карточку в Google
Maps (адрес, телефон, сайт, часы, рейтинг, число оценок, ссылка) →
открыть официальный сайт (что делают, часы, для ветклиник — неотложка
и специализации, на каких языках обслуживают, факты «коротко о месте»
(`facts`, `docs/card-spec.md` §9), логотип, соцсети, **прайс — только 6 услуг категории
из `docs/card-spec.md`, раздел «Цены»**) → записать строку со всеми полями
из `docs/card-spec.md`. На одно место — **5–8 минут**.

**Второй проход — «что говорят клиенты».** После того как CSV готов —
файлы `review-insights/<slug>.json` по инструкции
`docs/playbooks/review-insights.md` (кому: ≥ 20 оценок и ≥ 5 отзывов с
текстом за полгода; языки — `en` + языки города). Можно отдельным PR.

**Не включать:**
- закрытые места: «Permanently closed» / «Trvalo zatvorené» на Google,
  сайт не работает и нет активности за год. Такое место не добавлять
  вовсе (столбец `closed` — только для мест, которые закрылись уже
  после того, как попали на сайт; `docs/card-spec.md` §11);
- дубли: одно место с двумя карточками — одна строка;
- заведения без единого способа связи: нет телефона, почты и сайта.

Сети: каждый филиал — отдельная строка со своим адресом. Название
одинаковое — это нормально.

## 3. Тексты: правила

- **Своими словами.** Ни с Google, ни с сайтов, ни из отзывов ничего
  не копировать дословно (авторское право).
- **Только проверяемые факты:** что делают, для кого, чем отличаются
  (`Nonstop`, `CT and ultrasound`, `cats only`, `cage-free rooms`).
- **Запрещено:** «лучший», «профессиональный», «качественный»,
  «доступные цены», а также цены и обещания, которых нет в источниках.
- **Название и район в `short_description` не повторять**: они уже
  есть на карточке.
- **Текст не говорит больше данных карточки.** Английский в тексте —
  только если `en` в `languages_spoken`; «круглосуточно» — только при
  часах `24h`, неотложке или факте `supervision_24h`; паспорт — только
  при факте `pet_passport`. `check-city` ловит это и рекламные слова
  («modern», «professional», «nowoczesny», «profesionálny»…): для новых
  данных — ошибка, для старых — предупреждение. Урок переписанной
  Варшавы (2026-09-29): рекламные слова у 32 из 85 мест, «консультации на
  английском» у клиники с сайтом только на польском.
- **Улица и район в тексте — только из адреса и координат места.** Не
  знаешь — не пиши (адрес и так на карточке). `check-city` сверяет район
  в тексте с районом по координатам (для новых данных — ошибка) и улицу
  с адресом (предупреждение: текст может упоминать второй адрес места).
  Урок PR #199 (Кошице, 2026-09-29): у 9 из 11 мест без сайта текст
  «переселил» место на другую улицу и в другой район.
- **Каждый текст — про это место, с его сайта.** Один абзац на
  категорию с подставленным названием — не описание: он ничего не
  говорит о месте, а у Google это одинаковый текст на десятках страниц.
  Так были сделаны все описания Кошице и Варшавы (2026-09-28);
  `check-city` теперь ловит одинаковый текст у двух мест (сравнение
  без названия места). Нет сайта и ничего не известно — короткий текст
  только из того, что видно на карточке Google (категория, услуги из
  списка), без выдуманных деталей вроде «персонал поможет с выбором».
- **Часы — все дни, которые место указывает.** Строка только из
  выходных (`sa closed; su closed`) — это не часы: `check-city` её не
  засчитывает. Часов нигде нет — поле пустое и `hours: none (...)`.
- Пример:
  - `short_description`: `Nonstop vet with surgery, X-ray and ultrasound.`
  - `short_description_local`: `Nonstop ambulancia s chirurgiou, röntgenom a sonografom.`

## 4. Рейтинг Google и карточка на Google Maps

**Кто:** Claude Code CLI, в партии 0 (`AGENTS.md`, «Специализация»).
Исполнитель партий мест карточку не открывает, а копирует эти поля из
`candidates.csv` (раздел 2, «Партии»).

Карточка на Google Maps — источник рейтинга, адреса, часов и ссылки
«Маршрут». Её **почти всегда можно найти**: если не нашлась, скорее
всего искали не так.

### Как найти карточку — по порядку, пока не найдётся

1. По названию + город: `Dog's Beauty Bratislava`.
2. По адресу: `Mánesovo námestie 1 Bratislava` — открыть места в этом
   доме.
3. По телефону в поиске Google: `+421 948 995 901`.
4. По сайту: `dogsbeauty.sk` — Google часто показывает карточку справа.
5. Другие варианты названия: без «s.r.o.», на местном и английском,
   сокращение, имя владельца («MVDr. Novák»), название бренда сети.
6. У филиала сети — карточка **этого** адреса, а не общая карточка
   бренда.

Сверить найденное: совпадает адрес или телефон. Не совпадает — это
другое место.

### Что записать

- `google_maps_url`, `google_place_id` — всегда, если карточка найдена,
  даже без рейтинга. **Только копией с карточки** (кнопка «Поделиться» /
  адресная строка), никогда не составлять. Карточки нет или Google Maps
  не открывается — оба поля пустые, в `notes`:
  `maps: none (no Google Maps card: checked name, phone, address)` или
  `maps: none (Google Maps did not open - limited view)`. Честный пробел
  засчитывается `check-city`, выдуманная ссылка — нет (PR #144). В
  скопированной ссылке место записано дважды — номер карточки
  `!1s0x…:0x…` и place ID `!19sChIJ…`, и `check-city` сверяет, что это одно
  место: ссылка, собранная руками или из двух карточек, не пройдёт
  (Краков, партия 0: все 481 ссылка сошлись).
- `google_rating` и `google_rating_count` — ровно как на карточке, без
  округления. **Меньше 5 оценок — оба поля пустые.** На сайте такой
  рейтинг не показывается.
- `rating_observed_at` — дата проверки.
- Рейтинга нет — строка в `notes`, где искали:
  `rating: none (Google Maps by name, address, phone - 3 ratings)` или
  `rating: none (no Google Maps card: mobile service, checked name,
  phone, website)`.

**Юридически:** условия Google Maps запрещают массовый скрейпинг.
Смотреть и записывать вручную или полуавтоматически, без скриптов
с обходом защиты. **Решение владельца (2026-09-28):** рейтинг и отзывы
Google собираем так же, вручную; платный Places API не подключаем (по
его условиям рейтинг нельзя хранить у себя — только запрашивать при
каждом показе). Если Google потребует — рейтинг Google убирается с
сайта. Дальше — своя методика оценки и свои отзывы на сайте.

## 4.1 Часы работы

Где искать — по порядку:

1. Официальный сайт: «Otváracie hodiny», «Kontakt», подвал страницы.
2. Карточка на Google Maps — у Antigravity это `opening_hours` из
   `candidates.csv` (раздел 2, «Партии»), Maps не открывать.
3. Facebook-страница заведения (раздел «Информация»).

- Формат — `docs/card-spec.md`, раздел 5. `hours_source_url` — где

- Работают только по записи (частые у грумеров и дрессировщиков) —

- Часы нигде не опубликованы — `opening_hours` пустое, в `notes`:
  `hours: none (site, Google Maps, fb - not published)`.

## 5. Логотипы

**Цель — логотип у как можно большего числа заведений** (ориентир:
≥ 80 % записей). Карточка с инициалами вместо логотипа выглядит
заброшенной. У конкурента tippytaps.sk логотип почти у всех, и берут
они его именно так: с сайта или из соцсети заведения.

### Где искать — по порядку, до первого подходящего

1. **Шапка официального сайта:** `<img>`/`<svg>` с `logo` в `src`,
   `alt` или `class`. SVG — лучший вариант.
2. **Иконки сайта:** `apple-touch-icon`, иконки из `manifest.json`
   (192/512 px), `favicon`, если он ≥ 128 px и это логотип, а не буква
   конструктора сайта (значок Wix/WordPress — не логотип).
3. **`og:image` сайта**, если это логотип, а не фото.
4. **Аватар официальной страницы в Facebook.**
5. **Аватар официального аккаунта в Instagram** (обычно 150–320 px —
   подходит).
6. **Для филиала сети** — логотип бренда с сайта сети. Один файл на
   все филиалы, в `logo_file` у каждого одно и то же имя.

Аватар из соцсети годится, **если это логотип**: знак, надпись с
названием, эмблема. Фото собаки, людей, помещения или случайная
картинка — не логотип, идём дальше по списку.

### Нельзя

- Картинки из Google Maps / Google Business Profile, агрегаторов и
  каталогов (tippytaps, firmy.sk и т.п.) — это не официальный источник.
- Рисовать, генерировать, «восстанавливать» логотип или вырезать его
  из фото вывески.
- Обходить логин или защиту соцсетей скриптами. Открыть страницу в
  браузере и сохранить аватар вручную — можно. Скачивать скриптом с
  официального сайта — можно.

### Файл

- `website/public/logos/<slug-города>/<slug-заведения>.png|svg|webp`
  (у всех городов, включая Братиславу). Это же имя вписать в
  `logo_file`.
- **Не меньше 128 px по длинной стороне и 64 px по короткой** (аватар
  Instagram 150 px — нормально), достаточно 512 px, **не больше 200 КБ**.
  `check-city` не пропустит файл меньше или тяжелее, а сайт мелкий
  логотип не показывает — будут инициалы. **Иконка сайта (favicon
  16–72 px) — не логотип** (владелец, 2026-09-28: в Варшаве 45 мест
  получили размытую иконку 16–32 px вместо логотипа). Большой файл
  уменьшить перед коммитом.
  Желательно квадрат. Круглый аватар из соцсети сохранять как есть,
  квадратным файлом.
- В `notes` записать, откуда логотип: `logo: site header` /
  `logo: facebook avatar` / `logo: instagram avatar` / `logo: chain brand`.

### Проверить, как логотип выглядит

Сайт показывает логотип в белом квадрате примерно 64 × 64 px.
Открыть файл на белом фоне и уменьшить. **Не годится**, если:
- логотип белый или очень светлый: на белом фоне его не видно;
- SVG открывается пустым;
- логотип — узкая полоска, в которой ничего не прочитать;
- это фото, а не логотип.

Тогда искать дальше по списку выше: у многих заведений в соцсетях есть
цветной квадратный вариант.

### Если логотипа нет нигде

`logo_file` пустой, в `notes` — где смотрели: `logo: none (site —
no logo, fb — photo of dog, ig — none)`. Сайт покажет инициалы. В PR
перечислить такие заведения списком.

## 6. Деление города между аккаунтами

Город делится **партиями** (раздел 2, «Партии»): партии одного города
идут по очереди, разные города — параллельно. Отдельной сессии «только
категории X» больше нет: это партия с одной категорией.

С 2026-09-29 (`AGENTS.md`, «Специализация»): партия 0 — Claude Code CLI,
партии мест — Antigravity. Партии мест могут делить две установки
Antigravity по категориям: номера кусков каждой вписывает проверяющий в
таблицы их задач, чтобы файлы `businesses-<NN>-…` не совпали. `prices.csv`
у них общий: при конфликте в нём оставить строки обеих сторон.

## 7. Проверка перед PR

**Во время работы — ворота после каждого куска** (раздел «Партии»,
`npm run gate -- <slug>`). Перед PR все куски партии — `GATE PASS`, и
`check-city` это сверяет (таблица «Gates»).

**Главное — скрипт проверки качества:**

```
cd website && npm run check-city -- <slug-города>
```

Он должен напечатать `READY`. `NOT READY` — дособрать то, что в
строках `FAIL`, и то, что в списке «Missing without a search note».
Минимумы по полям — `docs/card-spec.md`, «Минимум качества».

**Второй скрипт — сверка с сайтами мест (нужен интернет):**

```
cd website && npm run verify-city -- <slug-города>
```

Должен напечатать `VERIFIED`. Он открывает сайт каждого места и
проверяет: домен существует и сайт отвечает; телефон из
`businesses.csv` написан на сайте (главная или «kontakt»); нет
заметки «prices: none (no cenník page …)», когда на сайте есть ссылка на
прайс; факт с доказательством (`card_payment: <url>`) назван на этой
странице (оплата картой, аптека, паспорт, парковка, натуральная
косметика, без клеток, прививки, 24 часа — на sk/pl/en). Не больше 25 %
фактов без совпадения. Урок второй Варшавы (2026-09-28): один набор
«карта, паспорт, аптека» у 28 клиник, «доказательство» — главная, где
этого нет. Доказательство — **страница, где факт написан**, не главная. Телефона на сайте нет — допустимо у немногих мест (номер
картинкой, форма записи), но не больше 25 %. Урок первой Варшавы
(2026-09-27): `check-city` был `READY`, а 54 из 66 телефонов и 11
доменов оказались придуманными. **Телефон и сайт — только копировать с
карточки Google Maps или сайта места, не набирать по памяти и не
«восстанавливать».**

Он же ищет **каждую цитату из `evidence*.csv` на её странице** (раздел
1.4): не больше 10 % цитат без совпадения, и каждая такая — в списке.
Страницы, которые скрипт прочесть не может (соцсети, PDF, сайты на
JavaScript), он перечисляет отдельно — проверяющий открывает 5 из них.

Плюс вручную:
- CSV открывается как таблица; в каждой строке столько же столбцов,
  сколько в заголовке.
- `category` — только из шести значений.
- `short_description` и `short_description_local` не длиннее 100
  символов.
- Нет дублей: одинаковые телефон или адрес у разных строк — только если
  это разные услуги одной фирмы.
- Логотипы просмотрены на белом фоне (раздел 5).
- Открыть 5 случайных ссылок `google_maps_url` и 5 `source_url` цен —
  открываются нужное место и нужный прайс.
- Колонки `animals` и `photo_urls` пустые.

## 8. PR

Заголовок: `City data: <Город> — партия <N> (<категория>)`, база PR —
`city/<slug>`. В описании:
- **самопроверка из `docs/playbooks/quality.md` (§2)**, заполненная;
- **вывод `npm run check-city -- <город>` и `npm run verify-city -- <город>` целиком**;
- сколько заведений по каждой категории;
- сколько с рейтингом, с коротким описанием, с логотипом;
- что не нашлось и почему (кратко);
- источники, которые использовались, и какие каталоги сверяли для
  полноты;
- где инструмент не сработал (сайт не открылся, урезанная карточка
  Maps) — список мест и что именно; у трети партии и больше — раздел
  `## Открытый вопрос` (`quality.md`, правило 9).

**После ревью:** правки — новыми коммитами в ту же ветку (сначала
`git pull`), без force-push; в PR — комментарий по каждому пункту ревью
(«сделано: …» / «ссылка: …» / «убрано»), вывод `check-city` целиком.

Если что-то неясно так, что нужен ответ владельца, — действовать по
`AGENTS.md`, раздел «Если задача неясна»: сделать всё, что можно,
вопрос вынести в PR.

## Что происходит после мерджа

Код для нового города не нужен: сборка Vercel загружает все
`data/cities/*/` в базу (seed), главная и выбор города уже работают на
любое число городов (PR #134, проверено на Кошице). Новый язык — да:
сначала `docs/playbooks/add-language.md`.

Проверяющий перед мерджем: `check-city` → `READY` и `verify-city` →
`VERIFIED` на ветке PR, 5 цитат из списка «cannot read» открыть руками, ручная
выборка (ссылки, координаты, 5–10 фактов по сайтам, 3–5 цен по прайсам),
локальная сборка с сидом города. **Каждую найденную ошибку — сразу в эту
инструкцию или в `check-city`** (владелец, 2026-09-27: добавление
городов должно становиться автоматическим).
