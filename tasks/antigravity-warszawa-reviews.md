# Задача: Warszawa — сводки отзывов

**Исполнитель:** Antigravity (Desktop / Hub)
**Роль:** Content agent.
**Тип:** сводки отзывов, объём большой (83 места).
**Ветка:** `antigravity/warszawa-reviews`
**Зависимости:** нет; порядок — после `antigravity-kosice-reviews-longer.md`
(она меньше и по уже знакомому городу). Начать от свежего `main`.

Решение владельца (2026-09-28): сводки отзывов делает Antigravity.
В Варшаве сводок нет ни у одного места.

Перед работой — `docs/playbooks/quality.md` и
`docs/playbooks/review-insights.md`.

## Что сделать

Все места Варшавы с ≥ 20 оценками в Google — 83 места (список — в
`data/cities/warszawa/businesses.csv`, столбец `google_rating_count`;
два места с меньшим числом не брать). Начинать с мест с наибольшим
числом оценок.

- Для каждого места: карточка Google Maps (ссылка — `google_maps_url`
  в данных), сортировка «Najnowsze», отзывы с текстом за последние
  6 месяцев; меньше 5 — за 12, потом за 24 месяца (плейбук, «Для каких
  мест»). ≥ 5 — сводка по плейбуку за самый короткий подходящий период,
  `period_from` — начало этого периода. И за 24 месяца < 5 — место в
  таблицу «без сводки» с реальным числом (сайт покажет короткий блок).
- Файл: `data/cities/warszawa/review-insights/<slug>.json`, языки **`en`
  и `pl`** (языки сводки — из `city.json`: `pl`). Польский — живой, не
  перевод с английского.
- Можно сдавать двумя PR (например, ветклиники, потом остальные), если
  так удобнее, — каждый с таблицей и выводом `check-city`.

## Чего не делать

- Не выдумывать и не «оценивать» (quality.md, правила 1, 7).
- Не цитировать отзывы и не называть авторов.
- Не добивать тексты общими фразами до нужной длины.
- Не трогать `businesses.csv` (его сейчас правит Mac — описания), цены,
  код сайта, другие города.

## Готово, когда

- **PR открыт** (коммит — не сдача), заголовок `Warszawa: review summaries`.
- `cd website && npm run check-city -- warszawa` → `READY`, вывод в PR.
- В PR — таблица по всем местам: ссылка на Maps, отзывов с текстом за
  6 / 12 / 24 месяца, какой период взят, сводка есть / нет и почему.
- Самопроверка `quality.md` (§2) в PR.

## Ревью ветки `antigravity/warszawa-reviews` (коммит 440f614) — не принято

«Левая рука» по указанию владельца, 2026-09-28. 63 файла, формат
правильный, тексты не повторяются. Но **числа и содержание не похожи на
прочитанную ленту отзывов**:

1. **Числа невозможные.** `petsy-domowy-hotel-dla-psow-i-kotow-warszawa`:
   89 отзывов с текстом за полгода при 120 оценках за всю жизнь места;
   `psybrothers-salon-groomerski`: 41 из 77. `check-city` (ветка
   `claude/check-city-templates`) теперь это ловит: число за период
   больше половины всех оценок — ошибка.
2. **Сводка расходится с видимыми отзывами.**
   `calodobowa-klinika-weterynaryjna-marysin`: из трёх свежих отзывов,
   что Google показывает первыми, два критических — 1300 zł за анализ
   крови ночью и неудачный забор крови у старой собаки. В сводке: персонал
   — «positive, 50», результаты — «positive, 29» («спасают после ДТП,
   отравлений, заворота желудка»), цены — «mixed». Критики лечения нет
   ни в одной карточке.
3. **Одинаковая форма у всех 63:** ровно по 85 строк, у 43 все три
   карточки «positive», период у всех один. Прочитать ленты по 100–170
   отзывов у 63 мест за час вручную нельзя.

**Что делать.** Не править точечно — переделать по ленте каждого места.
Для каждой сводки в PR — **доказательство чтения**: даты всех отзывов с
текстом за период (список) и для каждой карточки 2–3 даты отзывов, на
которых она основана. Карточка с критикой — если критика есть в ленте
(`mixed`/`negative`). Периоды — ступенями 6 → 12 → 24 месяца (плейбук,
новая редакция). До PR: `check-city -- warszawa` с проверками из
`claude/check-city-templates` — без ошибок.
