# Задача: город Kraków — второй польский город, партиями

**Исполнитель:** Claude Code CLI (Mac)
**Роль:** Data agent.
**Тип:** новый город (до 100 мест), куски по 10 мест с воротами, партия (PR) — 1–3 куска.
**Ветка PR:** `city/krakow` (ветка города; в `main` город уводит
проверяющий одним PR, когда готовы все партии).
**Зависимости:** нет. Начать от свежего `main`.

Передано от Antigravity (Mac) владельцем 2026-09-29: задача ещё не была
начата, а Antigravity (Mac) занят описаниями Варшавы. Урок оттуда уже в
правилах — `check-city` ловит рекламные слова и тексты, которые говорят
больше данных (`add-city.md` §3).

Решение владельца (2026-09-28): следующие города — Kraków (Польша) и
Prešov (Словакия, задача Antigravity IDE). Братислава — образец
(`docs/growth-strategy.md` §0): делать ровно по шаблону, не больше и не
меньше. Польский язык уже на сайте (Варшава, PR #169).

**Новое с 2026-09-28 (владелец) — прочитать до начала:**
`docs/playbooks/quality.md`, правила 8 и 9, и `docs/playbooks/add-city.md`,
разделы «Партии» и 1.4. Коротко: одна сессия — одна партия; к каждому
значению с сайта — цитата со страницы в `evidence-<NN>-<категория>.csv`;
не открылось — `none (...)`, это засчитывается. **С 2026-09-29:** правило
10 — кусками по 10 с `npm run gate` после каждого.

## Подготовка (один раз, до партии 0)

Для карточек Google Maps (ссылка, рейтинг, число оценок, часы) нужен
настоящий браузер: страницу Maps без него не прочитать. Если MCP
Playwright ещё не подключён — владелец или сам агент:
`claude mcp add playwright npx @playwright/mcp@latest`, затем
перезапустить `claude`. Проверка: открыть в браузере карточку любого
места в Кракове и прочитать рейтинг. Страница согласия Google («Zanim
przejdziesz do Google») — нажать «Odrzuć wszystko». Не получается открыть
Maps — не собирать по памяти: остановиться и написать об этом в PR
партии 0 (`quality.md`, правило 9).

### Ответы проверяющего по партии 1 (PR #200, 2026-09-29)

- **Arka — не Nonstop.** Под заголовком «Całodobowy dyżur weterynaryjny»
  сайт сам даёт часы пн–пт 9–20, сб 9–13, вс 9–12, а правило Nonstop
  требует 24h все дни. Оставить как сделано: часы с сайта,
  `emergency_24_7` пусто, `emergency_note` — их заявление о дежурстве.
- **Retina — `en` ставить.** `card-spec.md` §8 считает языковую версию
  сайта языком обслуживания, у Retina это настоящая английская версия
  (WPML). Доказательство — цитата с английской страницы, `source_url` —
  `https://www.weterynarz-okulista.pl/?lang=en`; `check-city` теперь
  принимает такую страницу для `languages:<код>`. Сделать в партии 2:
  поправить строку Retina в куске 01, дописать цитату и **заново пройти
  ворота куска 01** (`npm run gate -- krakow 01-vet`).
- `languages:uk` с польским «ukraińskim» теперь проходит проверку слов.

### Партия 0

1. Ветка `city/krakow` от свежего `main`, если её нет:
   `git fetch origin && git push origin origin/main:refs/heads/city/krakow`.
2. `data/cities/krakow/city.json` — `locale` `pl`, `locales` `["pl"]`,
   `in_city`: `{"en": "in Kraków", "pl": "w Krakowie"}`, `timezone`
   `Europe/Warsaw`, `currency` `PLN`.
3. `data/cities/krakow/districts.geojson` — 18 dzielnic из
   OpenStreetMap скриптом `scripts/fetch-districts.ts` (как в Варшаве);
   `admin_level` проверить в OSM и написать в PR. `name` — как в
   обиходе («Stare Miasto», «Nowa Huta»), без «Dzielnica I». Падеж `in`
   («na Kazimierzu», «w Nowej Hucie») — только если уверен, иначе
   только `en`.
4. `data/cities/krakow/candidates.csv` — все найденные работающие места
   шести категорий: название, ссылка Maps и число оценок **копией** с
   карточки, сайт. Запросы — главные варианты из
   `docs/seo/keywords/pl.md` («weterynarz kraków», «groomer kraków»,
   «hotel dla psów kraków», «szkolenie psów kraków», «sklep zoologiczny
   kraków», «petsitter kraków»); сверка полноты — 1–2 каталога на
   категорию (только как список названий). Закрытые места не включать.
5. PR в `city/krakow`: сколько кандидатов по категориям, какие запросы и
   каталоги, что с районами.

### Партии 1…n

**Кусками по 10 с воротами** (`quality.md`, правило 10): 10 мест в файле
куска `businesses-<NN>-<категория>.csv` (+ `evidence-<NN>-<категория>.csv`)
→ `cd website && npm run gate -- krakow` → `GATE FAIL` — исправить по
списку, заново открыв источник, и снова (3-й круг: несошедшееся — пусто
и `none (...)`); `GATE PASS` — закоммитить кусок вместе со штампом
`data/cities/krakow/checks/<NN>-<категория>.json` → следующие 10. `NN` —
номер куска в городе по порядку.

Места из строки таблицы — по **`docs/playbooks/add-city.md`**, поля — по
**`docs/card-spec.md`**: файлы `businesses-<NN>-<категория>.csv` и
`evidence-<NN>-<категория>.csv`, цены в злотых — дописать в
`prices.csv`, логотипы — `website/public/logos/krakow/` (до 200 КБ, не
меньше 128 px). `*_local` — живой польский. У ветклиник — языки
обслуживания (иностранные, не `pl`), каждый — с цитатой. Строки прошлых
партий не трогать. Сводки отзывов не делать — это отдельная задача
после того, как город в `main`.

## Уроки Варшавы и Кошице

- **Тексты — про каждое место, с его сайта.** Один абзац на категорию
  с подставленным названием не принимается (`check-city` ловит). Цитата
  с сайта для `description` — в `evidence`.
- **Телефоны и сайты — с карточки и сайта места, не набирать.** В
  первой версии Варшавы номера и домены были придуманы; `verify-city`
  это ловит.
- **Факты — каждый код с цитатой со страницы, где это написано.** Набор
  `card_payment;pet_passport;pharmacy_on_site` у всех клиник по главной
  странице — возврат PR. Ничего нет — `facts: none (site checked:
  ...)`.
- **Цены: не придумывать вес.** Прайс по породам — одна строка без веса,
  `price_from`/`price_to` — самая низкая и самая высокая цена
  (`card-spec.md`, «Цены»); у каждой цены — цитата строки прайса.
  Страницу «cennik» искать на каждом сайте, заметка `prices: none (...)`
  — своя у каждого места.
- Часы — `closed`, не `off`; слаги — только `a-z`, `0-9` и одиночные
  дефисы (`check-city` ловит оба).
- Ссылка Google Maps, `google_place_id`, координаты и оценка — только
  копией с карточки.
- После ревью — только новые коммиты, без force-push.

## Если инструмент не работает

Не открылся сайт или Google Maps, нет данных — поле пустое, в `notes`
`<поле>: none (<где смотрел, что не открылось>)`. Это засчитывается,
`check-city` пропускает. Если так у трети мест партии и больше — не
собирать дальше: открыть PR с тем, что есть, и описать проблему в
разделе `## Открытый вопрос`. Сдать меньше мест с объяснением —
нормально; возврат PR бывает за выдумку, не за честный пробел.

## Чего не делать

- Не выдумывать и не «оценивать» (quality.md, правила 1, 7).
- Не брать больше мест, чем в строке таблицы.
- Не копировать тексты с сайтов дословно и не брать тексты Варшавы.
- Не переводить цены в евро.
- Не трогать код сайта, файлы других городов и прошлых партий.

## Готово, когда (для каждой партии)

- **PR открыт в `city/krakow`** (коммит — не сдача), заголовок
  `City data: Kraków — партия <N> (<категория>)`.
- У каждого куска партии — `GATE PASS` (штамп в `checks/`).
- `cd website && npm run check-city -- krakow` → `READY` (с таблицей
  «Gates») и `npm run verify-city -- krakow` → `VERIFIED` (с партии 1),
  вывод обоих целиком в PR.
- В PR — самопроверка `quality.md` (§2), таблица заполненности по
  полям, что не нашлось и почему, где инструмент не сработал.
