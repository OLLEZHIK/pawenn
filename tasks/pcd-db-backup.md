# Задача: ежедневная копия боевой базы на ПК

**Исполнитель:** Claude Code CLI (ПК, диспетчер) — делает сам, контейнерам `agyN` не раздаёт.
**Роль:** инфраструктура (резервная копия).
**Тип:** разовая настройка + ежедневный запуск по расписанию.
**Ветка PR:** `main` (только скрипт и инструкция, без данных).
**Ветка:** `pcd/db-backup`
**Зависимости:** нет.
**Срочность:** высокая — сделать до следующей раздачи задач агентам.

**Сейчас («левая рука», 2026-10-09):** начать. Подтверждение владельца
на автозапуск и контейнер есть (ниже, «Разрешение»), строку подключения
к Neon даёт владелец.

## Зачем

Владелец, 2026-10-09: «дай задание диспетчеру пусть сделает локальную базу
данных на компьютере раз в день пусть обновляет её».

Каталог (места, цены, сводки, логотипы) и так лежит в git, и `seed` может
собрать его заново. Но две таблицы есть **только в Neon**:
- `Review` — отзывы, которые посетители оставляют на сайте;
- `ClickEvent` — клики «позвонить / сайт / маршрут».

Если с Neon что-то случится (аккаунт, ошибочная миграция, удаление), без
копии они пропадут. Нужна копия всей базы на ПК, которая обновляется раз
в день, и файлы дампов за прошлые дни, чтобы можно было откатиться.

## Разрешение

Автозапуск по расписанию и новый контейнер на ПК — критическая
инфраструктура (`AGENTS.md`, п. 6). Владелец сам поручил это сделать в
чате 2026-10-09: это подтверждение **только на то, что описано ниже**
(один контейнер Postgres для копии и одна задача Планировщика). Всё
остальное — как обычно, с отдельного «да».

## Что сделать

### 1. Строка подключения — от владельца, не в git

- Попросить владельца положить строку подключения Neon **без `-pooler`**
  в хосте в файл `D:\backup\pawenn\neon.env` одной строкой:
  `NEON_URL=postgresql://…`. Neon подключён через Vercel, поэтому
  строка лежит там: Vercel → проект → вкладка **Storage** → база Neon →
  вкладка **.env.local** → **Show secret** → значение
  `DATABASE_URL_UNPOOLED` (или `POSTGRES_URL_NON_POOLING`; имя может
  быть с префиксом). Другой путь — кнопка **Open in Neon** там же →
  **Connect**, переключатель **Connection pooling** выключить.
- Файл — только на ПК. Не коммитить, не печатать в терминал и в отчёты,
  не передавать в контейнеры `agyN`. В логах — только хост без пароля.
- Права на файл: только учётная запись владельца
  (`icacls D:\backup\pawenn\neon.env /inheritance:r /grant:r "%USERNAME%:R"`).

### 2. Версия Postgres

Один раз узнать версию Neon:
`docker run --rm --env-file D:\backup\pawenn\neon.env postgres:17 sh -c 'psql "$NEON_URL" -Atc "show server_version"'`.
Для дампа и для локальной базы брать образ `postgres:<та же основная
версия>` (`pg_dump` не должен быть старше сервера).

### 3. Локальная база — контейнер `pawenn-db-backup`

```
docker volume create pawenn-db-backup
docker run -d --name pawenn-db-backup --restart unless-stopped ^
  -e POSTGRES_PASSWORD=<свой локальный пароль> -e POSTGRES_DB=pawenn ^
  -p 127.0.0.1:5433:5432 -v pawenn-db-backup:/var/lib/postgresql/data postgres:<версия>
```

- Порт только на `127.0.0.1` и не `5432` (там может быть база для
  разработки). Агентам `agyN` адрес этой базы не давать: в ней имена
  авторов отзывов.
- Локальный пароль — тоже в `D:\backup\pawenn\neon.env`
  (`LOCAL_URL=postgres://postgres:<пароль>@host.docker.internal:5433/pawenn`).

### 4. Скрипт `backup-db.ps1`

Положить в репозиторий как `docs/pc-agents/db-backup/backup-db.ps1`
(правки в `docs/` не запускают сборку Vercel), рабочая копия —
`D:\backup\pawenn\backup-db.ps1`. Каждый запуск:

1. **Дамп:** `pg_dump "$NEON_URL" -Fc --no-owner --no-acl` (через
   `docker run --rm --env-file …neon.env postgres:<версия>`) в
   `D:\backup\pawenn\daily\pawenn-YYYY-MM-DD.dump`. Только чтение:
   никаких записей в Neon.
2. **Проверка файла:** размер больше 0 и `pg_restore --list` читает его
   без ошибки. Не прошло — файл переименовать в `*.failed`, локальную
   базу не трогать, в лог `FAIL` с причиной.
3. **Обновить локальную базу:** `pg_restore --clean --if-exists
   --no-owner --no-acl -d "$LOCAL_URL"` этим же файлом.
4. **Сверка:** в Neon и в локальной базе посчитать строки `"City"`,
   `"Business"`, `"PriceItem"`, `"Review"`, `"ClickEvent"`
   (`select count(*)`). Должны совпасть; клики могут отличаться на
   несколько штук (пришли во время дампа) — это не ошибка, если в
   локальной не больше, чем в Neon.
5. **Лог:** одна строка в `D:\backup\pawenn\backup.log`: дата, `OK` или
   `FAIL`, размер файла, пять чисел из сверки.
6. **Хранить:** дампы за последние 14 дней + дамп 1-го числа каждого
   месяца за год; остальные удалять.
7. **Вне ПК (раз в неделю, по воскресеньям):** если на ПК есть Google
   Drive для компьютера — копировать последний дамп в папку
   `Pawenn backup` на нём. Нет Google Drive — написать владельцу в
   отчёте, куда предлагаешь класть копию; без его ответа не настраивать.

Neon на бесплатном тарифе засыпает; дамп его будит на несколько минут
раз в сутки — это нормально.

### 5. Планировщик Windows

Задача `Pawenn DB backup`, каждый день в 04:17, через
`Register-ScheduledTask`:
- действие: `powershell -NoProfile -ExecutionPolicy Bypass -File D:\backup\pawenn\backup-db.ps1`;
- настройки: `New-ScheduledTaskSettingsSet -StartWhenAvailable`
  (ПК был выключен в 04:17 — запустить при включении), не дольше 1 часа;
- Docker Desktop должен работать: скрипт сначала проверяет `docker info`,
  нет Docker — `FAIL docker not running` в лог.

### 6. Проверка восстановления (один раз)

После первого запуска убедиться, что из копии реально можно поднять
сайт: в своём клоне `website/.env.local` временно направить на
локальную копию, `npx next build && npx next start -p 3200`, открыть
главную и любую страницу места. Потом вернуть `.env.local` как был.

### 7. Инструкция

`docs/pc-agents/db-backup/README.md`, коротко: где лежат файлы, как
проверить лог, как восстановить боевую базу из дампа
(`pg_restore --clean --if-exists --no-owner --no-acl -d "<строка новой базы>" <файл>`
— восстановление в Neon только с прямого «да» владельца), как сменить
строку подключения.

## Чего не делать

- Не писать в Neon ничего (только `pg_dump` и `select count(*)`).
- Не коммитить дампы, `neon.env`, пароли и строки подключения; не
  вставлять их в PR, отчёт и поручения агентам.
- Не открывать локальную базу наружу (только `127.0.0.1`).
- Не добавлять секреты в GitHub Actions и не трогать Vercel — это
  другое решение, только с «да» владельца.

- Задача Планировщика создана; на следующий день в `backup.log` есть
