# Задача: город Prešov — третий словацкий город по шаблону

**Исполнитель:** Antigravity IDE
**Роль:** Data agent.
**Тип:** новый город, объём средний (сколько мест реально есть, до 100).
**Ветка:** `antigravity/city-presov`
**Зависимости:** `tasks/ide-kosice-descriptions-hours.md` — сначала она
(там новые проверки `check-city`, и её уроки нужны здесь). Начать от
`main` после её мерджа.

Решение владельца (2026-09-28): следующие города — Prešov (Словакия) и
Kraków (Польша, задача Mac). Братислава — образец
(`docs/growth-strategy.md` §0): делать ровно по шаблону, не больше и не
меньше. Словацкий язык уже на сайте.

## Уроки Кошице и Варшавы (прочитать до начала)

- **Тексты — про каждое место, с его сайта.** Один абзац на категорию
  с подставленным названием не принимается (`add-city.md` §3,
  `check-city` ловит). Все описания Кошице и Варшавы пришлось
  переписывать.
- **Часы — все дни, что указывает место.** Строка из одних выходных
  (`sa closed; su closed`) — не часы. Нет нигде — пусто и
  `hours: none (...)`.
- Ссылка Google Maps, `google_place_id`, координаты и оценка — **только
  копией** с карточки; нет карточки — пусто и `maps: none (...)`.
- Телефон и сайт — сверить с сайтом места (`verify-city`); придуманный
  номер или несуществующий домен — возврат PR.
- Каждый код `facts` — со ссылкой на страницу, где это написано
  (`parking: <URL>`); ничего нет — `facts: none (site checked: ...)`.
- Цены: размер/порода без веса — одна строка без веса (`card-spec.md`,
  «Цены»); «prices: none (...)» — своя заметка у каждого места, где
  смотрел.
- Клиника и её врач с отдельными карточками Google — одно место.
- После ревью — только новые коммиты, без force-push.

## Что сделать

Всё — по **`docs/playbooks/add-city.md`** (город `Prešov`, slug
`presov`, страна `SK`, язык `sk`), поля — по **`docs/card-spec.md`**,
качество — по **`docs/playbooks/quality.md`**.

1. `data/cities/presov/city.json` — `locale` `sk`, `locales` `["sk"]`,
   `in_city`: `{"en": "in Prešov", "sk": "v Prešove"}`, `timezone`
   `Europe/Bratislava`, `currency` `EUR`.
2. `data/cities/presov/districts.geojson` — части города из
   OpenStreetMap скриптом `scripts/fetch-districts.ts` (как в Кошице).
   Проверить в OSM, есть ли у Prešova границы частей города и какой у
   них `admin_level`; что взял — в PR. Если границ частей в OSM нет —
   файл не делать и написать об этом в PR (не рисовать границы самому).
   Падеж `in` («v Solivare») — только если уверен, иначе только `en`.
3. `data/cities/presov/businesses.csv` — все 6 категорий, все поля
   карточки, включая `facts`. Закрытые места не добавлять. Если мест в
   городе больше 100 — брать с наибольшим числом оценок в Google,
   правило отбора и число кандидатов — в PR.
4. `data/cities/presov/prices.csv` — только опубликованные прайсы, в евро.
5. Логотипы — `website/public/logos/presov/`, до 200 КБ.
6. **Сводки отзывов не делать** — после мерджа это отдельная задача
   Antigravity (Desktop).

Запросы для поиска — главные варианты из `docs/seo/keywords/sk.md`
(«veterinár prešov», «strihanie psov prešov», «hotel pre psov prešov»,
«výcvik psov prešov», «chovateľské potreby prešov», «venčenie psov
prešov»); сверка полноты — 1–2 каталога на категорию.

## Чего не делать

- Не выдумывать и не «оценивать» (quality.md, правила 1, 7).
- Не копировать тексты с сайтов дословно.
- Не трогать код сайта и файлы других городов.

## Готово, когда

- **PR открыт** (коммит — не сдача), заголовок `City data: Prešov`.
- `cd website && npm run check-city -- presov` → `READY` и
  `npm run verify-city -- presov` → `VERIFIED`, вывод обоих целиком в PR.
- В PR — самопроверка `quality.md` (§2), таблица заполненности по
  полям, сколько мест по категориям, какие каталоги сверяли, что не
  нашлось и почему, что с районами.
