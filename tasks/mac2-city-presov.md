## Что сделать в каждой партии

Места из строки таблицы — по `docs/playbooks/add-city.md`, поля — по
`docs/card-spec.md`: файл куска `businesses-<NN>-<категория>.csv`,
цитаты — `evidence-<NN>-<категория>.csv`, цены — дописать в
`prices.csv`, логотипы — `website/public/logos/presov/` (до 200 КБ, не
меньше 128 px).

**Google Maps не открывать.** Столбцы с карточки — копией из строки
места в `candidates.csv` (`add-city.md`, «Партии», таблица «Откуда»):
`google_maps_url`, `google_rating`, `google_rating_count` — как есть;
`rating_observed_at` — `observed_at`; `google_place_id`, `lat`, `lng` —
из той же ссылки (после `!19s`, `!3d`, `!4d`); часы, адрес, телефон — с
сайта, а нет на сайте — из `candidates.csv` (у часов тогда
`hours_source_url` — ссылка Maps). `check-city` сверяет с
`candidates.csv`: другое значение не пройдёт ворота. Мобильная служба
без помещения (часто `PET_SITTING`) — без координат,
`coords: none (mobile service, no premises)`.

Кусками по 10, после каждого — ворота (`quality.md`, правило 10):
10 мест → `cd website && npm run gate -- presov` → `GATE FAIL` —
исправить по списку, заново открыв сайт, и снова (3-й круг: несошедшееся
— пусто и `none (...)`); `GATE PASS` — закоммитить кусок вместе со
штампом `data/cities/presov/checks/<NN>-<категория>.json` → следующие 10.

## Уроки Кошице и Варшавы

- **Тексты — про каждое место, с его сайта.** Один абзац на категорию
  с подставленным названием не принимается (`check-city` ловит). Цитата
  с сайта для `description` — в `evidence`. Сайта и соцсети нет — текст
  только из того, что есть в строке (категория, название, адрес), без
  деталей и без улиц, которых нет в `address` (урок PR #199).
- **Часы — все дни, что указывает место.** Строка из одних выходных
  (`sa closed; su closed`) — не часы. Только по записи — `by-appointment`.
- Телефон и сайт — сверить с сайтом места (`verify-city`); придуманный
  номер или несуществующий домен — возврат PR.
- Каждый код `facts` и `specialties` — цитата со страницы, где это
  написано (не главная, если там этого нет); ничего нет — `facts: none
  (site checked: ...)`. `appointment_only` — только по прямым словам
  («len na objednávku»).
- Цены: размер/порода без веса — одна строка без веса (`card-spec.md`,
  «Цены»); у каждой цены — цитата строки прайса; «prices: none (...)» —
  своя заметка у каждого места, где смотрел.
- Клиника и её врач с отдельными строками в `candidates.csv` — одно
  место; вторую строку не собирать, написать в PR.
- После ревью — только новые коммиты, без force-push.

## Если инструмент не работает

Не открылся сайт, нет данных — поле пустое, в `notes`
`<поле>: none (<где смотрел, что не открылось>)`. Это засчитывается,
`check-city` пропускает. Если так у трети мест партии и больше — не
собирать дальше: открыть PR с тем, что есть, и описать проблему в
разделе `## Открытый вопрос`. Сдать меньше мест с объяснением —
нормально; возврат PR бывает за выдумку, не за честный пробел.

## Чего не делать

- Не выдумывать и не «оценивать» (quality.md, правила 1, 7).
- Не открывать Google Maps и не искать там места, которых нет в
  `candidates.csv` (нашёл на сайте другое место — напиши в PR).
- Не брать больше мест, чем в строке таблицы.
- Не копировать тексты с сайтов дословно (цитаты — только в `evidence`).
- Не трогать код сайта, файлы других городов, `candidates.csv` и прошлые
  партии.

## Готово, когда (для каждой партии)

- **PR открыт в `city/presov`** (коммит — не сдача), заголовок
  `City data: Prešov — партия <N> (<категории>)`.
- У каждого куска партии — `GATE PASS` (штамп в `checks/`).
- `cd website && npm run check-city -- presov` → `READY` (с таблицей
  «Gates») и `npm run verify-city -- presov` → `VERIFIED`, вывод обоих
  целиком в PR.
- В PR — самопроверка `quality.md` (§2), таблица заполненности по
  полям, что не нашлось и почему, где инструмент не сработал.
