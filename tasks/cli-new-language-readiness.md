# Задача: подключение нового языка и страны — по скрипту, с проверкой (фронтенд)

**Исполнитель:** Claude Code CLI (локальный) — код сайта и дизайн не относятся к диспетчеру: он собирает только данные городов (владелец, 2026-10-02). Антигравити на ПК фронтенд не даём (`AGENTS.md`).
**Роль:** Frontend + скрипты.
**Тип:** код сайта и скрипты проверки; визуальная проверка в браузере (Playwright).
**Ветка PR:** `main`, ветки `cli/<slug>`.
**Зависимости:** нет.
**Срочность:** сегодня–завтра: следующие города (Praha, Wien, Budapest — `docs/pc-agents/backlog.md`) требуют новых языков.

**Сейчас (проверяющий, 2026-10-02):** начать с партии 1.

Зачем (владелец, 2026-10-02): города должны добавляться почти без участия человека, включая города с новым языком. Сейчас язык подключается вручную по `docs/playbooks/add-language.md` (7 мест в коде, папки сегментов, словарь) и без проверки полноты. Нужно: превратить это в скрипт плюс проверку, чтобы CLI на ПК мог подключить язык сам, а «левая рука» увидела по отчёту, что всё на месте.

Перед работой — `docs/playbooks/add-language.md`, `docs/architecture/multi-city.md`, `docs/playbooks/quality.md`.

## Что сделать

1. **`check-language <locale>`** (`website/scripts/check-language.ts`): язык есть в `LOCALES`, `DATE_LOCALE`, `COUNTRY_LANGUAGE`, `OG_LOCALE`, `BUSINESS_SEGMENT`, `CITY_SEGMENT`, `SLUGS` категорий, `PRICES_SEGMENT`, `SERVICE_SLUGS`, признаков (`attributePages.ts`), подписях услуг и специальностей, `GUIDE_SEGMENT`; папка страницы места `app/[lang]/<сегмент>/[slug]/` существует; словарь есть и **строки не равны английским** (допуск — список исключений: бренд, коды, числа); слаги уникальны внутри языка; `tsc --noEmit` чист. Вывод — таблица «пункт → OK/FAIL», код 1 при FAIL. Проверка должна работать для `sk` и `pl` сразу (регрессия).
2. **`add-language`**: делает механические шаги плейбука (запись в `locales.ts`, копия `en.ts` в `<locale>.ts` с пометкой `// TODO(translate)` у каждой строки, копия папки страницы места с новым `SEGMENT`, заготовки слагов с `TODO`), печатает, что осталось руками (перевод словаря — Antigravity по шагу 2 плейбука, слаги — по карте ключевых слов). `check-language` до заполнения даёт FAIL по TODO — так язык не уйдёт в `main` недоделанным. Плейбук `add-language.md` обновить под скрипты.
3. **Аудит строк:** пройти `/sk/` и `/pl/` в браузере (главная, категория, город, район, место, цены, статья, 404, формы) и найти английский текст интерфейса, meta, alt, aria-label, ошибки форм. Список — в PR; исправить в словарях и компонентах.
4. **`smoke <город>`** (Playwright): для города с `locales` — главная, категория, район, страница места, страница цен, статья (если есть) на каждом языке: ответ 200, один `h1`, нет битых картинок, нет английской строки на странице не-английского языка из списка словаря, JSON-LD разбирается. Вывод — таблица и код 1 при FAIL; подключить как пятые ворота в `ready-city` (`website/scripts/ready-city.ts`) там, где браузер доступен.
5. **Справочные страницы страны:** данные налога на собаку (SK) уже в `data/reference/sk/dog-tax.csv`, страниц нет. Сделать страницу «Daň za psa» по городу и по району (ставка, льготы, VZN, дата проверки, ссылка на источник — как в данных, ничего не додумывать) и общий шаблон справочной страницы страны, чтобы аналогичные данные Польши и других стран подключались данными. Заголовки и слаги — по `docs/seo/keywords/sk.md`; индексировать, только если данные есть.

## Чего не делать

- Не переводить словари самому: перевод — Antigravity (шаг 2 плейбука).
- Не менять слаги `sk` и `pl`, уже живущие в поиске.
- Не запускать продакшен-миграции и не трогать базу (`AGENTS.md`, «Критическая инфраструктура»).
- Не пушить каждый шаг: сборка Vercel ограничена, партию пушить целиком после проверки.
