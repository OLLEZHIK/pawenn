## Что сделать в каждой партии

1. `cd website && npm install` (один раз), затем
   `npm run verify-city -- <город>` — это и есть список работы.
2. По каждому месту из куска — открыть его сайт заново и решить:
   - **сайт не отвечает:** поискать новый официальный сайт или соцсеть
     места (не Google Maps). Нашёл — поменять `website`, цитата.
     Сайт закрыт и есть прямые слова «zatvorené / ukončili činnosť /
     zamknięte» — `closed` по `card-spec.md` §11, цитата. Нет ничего —
     **ничего не удалять**, в `notes`:
     `website: none (<что пробовал, дата>)`; закрытие решает проверяющий.
   - **телефона нет на сайте:** найти телефон на сайте (контакты, футер,
     страница филиала). Другой — заменить, цитата. Сайт его не пишет
     совсем — оставить как есть, в `notes`: `phone: not on site (<где
     смотрел>)`.
   - **факт не на своей странице:** найти страницу, где это написано, и
     поменять ссылку в цитате; не нашёл — убрать факт.
3. Каждое изменённое значение — строка в
   `data/cities/<город>/evidence-audit-<NN>.csv` (формат — как
   `evidence-*.csv` в Прешове: `business_slug,field,quote,source_url,observed_at`).
4. После куска — `npm run check-city -- <город>` → `READY` и
   `npm run verify-city -- <город>` → `VERIFIED`, коммит.

## Если инструмент не работает

Не открылся сайт, нет данных — поле пустое, в `notes`
`<поле>: none (<где смотрел, что не открылось>)`. Это засчитывается.
Если так у трети мест партии и больше — не собирать дальше: открыть PR
с тем, что есть, и описать проблему в разделе `## Открытый вопрос`.
Сдать меньше мест с объяснением — нормально; возврат PR бывает за
выдумку, не за честный пробел.
